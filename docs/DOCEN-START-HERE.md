# docen 전체 인수인계 — 다른 AI가 가장 먼저 읽을 문서

기준일: 2026-11-22. 작성 근거: 이 대화에서 확인 가능한 사용자 요청·정정·답변, 저장소의 AGENTS.md·분야별 계약·구현·검증 기록. 이 문서는 제품의 현재 기준과 작업 방법을 정리한 통합 입구다. 대화 원문 전체의 무손실 보관본은 아니다. 사라진 첨부 영상·접근하지 못한 개인 Notion·실기기 상태를 복원했다고 주장하지 않는다.

**이번 문서화는 앱 출시·새 native 빌드·도메인 인증 완료·PG 결제 개시를 뜻하지 않는다.** 상태는 아래의 증거 수준으로 구별한다. 이후 사용자 명시 지시가 이 문서보다 우선한다.

## 0. 5분 안에 알아야 할 현재 상황

1. 서비스 표시 이름은 앱·웹 모두 **소문자 docen**, 구매 도메인은 **docen.today**, 구매처는 **호스팅KR**이다. 이전 덕/Duck/duckduck/도슨/Dosen/Docen은 과거 이력이다. 오리 마스코트는 유지한다.
2. **새 도메인은 소개만 공개한다. 웹서비스는 아직 오픈하지 않는다.** 소개→추후 로그인→웹서비스가 목표 흐름이다. 지금은 시작/로그인 안내와 서버 제한을 유지한다.
3. 기존 테스트 주소는 https://duckduck-test.onrender.com 이다. 기존 앱·인증·native API·OAuth·어드민은 그 주소에서 유지한다. 인터넷에 접근 가능한 테스트 주소이며 초대 인증으로 보호했다고 하지 않는다.
4. 메일 발신 문제는 최신 사용자 확인 기준으로 해결됐다. 새 Resend 계정에서 도메인 Verified/Forge Ready, 사용자가 Render 키를 직접 등록했고 **실제 메일 수신→인증번호 확인→내부 진입 완료**를 확인했다. AI가 받은편지함을 직접 열어 확인한 것은 아니다.
5. 웹용 DNS는 사용자 캡처로 **A @ →216.24.57.1 / CNAME www →duckduck-test.onrender.com / TTL180** 저장을 확인했다. 마지막 공개 DNS 조회에서 www CNAME은 확인됐고 루트 A는 아직 응답에 없었다. **Render 도메인 Verified·TLS 발급·새 주소 HTTPS 접속은 미확인**이다.
6. 최신 확인한 서비스 배포는 구현96e3b48을 포함하는 b5631cdb1320fcadf1d479bf3c9807fc465d9e09, Render dep-dc1fj8mc6qcc73anm4u0, 2026-11-22T14:19:07.296071Z live다. 문서화 시작 시 로컬 HEAD는89489e6이다. 이 해시는 영구 최신이 아니므로 다음 작업 시 Git/Render를 조회한다.
7. 공개 요금은 사용자가 마지막에 **웹 표시 그대로 유지**하라고 했다. 현재 소스는 Lite 정상19,900/베타월16,900, Pro 정상55,900/베타월49,900, 연간총202,800/598,800, Business상담이다. 앞서 말한45,000/39,900·Lite에도 직접채팅 등은 현재 게시 내용과 다르므로 아래 충돌 기록을 읽는다. 문서 작업으로 가격·권한을 바꾸지 않는다.
8. 기존 미변경 계정은 무료 Pro 정책이다. 운영자가 개별 이용권을 관리한 회원은 그 이용권을 따른다. **Pro 권한·실제 결제·AI 원가 예산은 세 가지 별개**다. PG는 연결되지 않았다.
9. 사용자 원칙: docen에서 외부 연결 항목의 내용·날짜·시간·완료를 명시적으로 바꾸면 지원되는 원본도 바꾼다. 직접 만든 항목은 docen에서만 바꾼다. 원본 권한·버전·기기 제한을 우회하지 않는다. 실패·불가에는 채팅에서 이유와 대안까지 알린다.
10. 우선 앱과 웹에 집중한다. Windows EXE/Mac App Store는 검토 이력이며 지금 자동 개발/출시하지 않는다. AI 사무실도 재개 요청 전 보류다.

5. 변경 전에 git status로 사용자 변경을 확인한다. 코드와 문서가 다르면 그 차이를 기록한다. 코드의 잘못된 동작을 새로운 사용자 승인으로 간주하지 않는다.

## 2. 사용자와 협업하는 방식

- 한국어로 쉽게 설명한다. ‘어디를 누르는지’ 버튼 이름·화면 위치·다음 결과를 한 단계씩 제시한다. 기술 용어가 필요하면 짧게 뜻을 붙인다.
- **ㅇㄹ은 완료라는 뜻**이다. 직전 단계의 완료로 이해한다. API 키가 보인다거나 전체 출시가 끝났다는 식으로 의미를 확대하지 않는다.
- 사용자는 동일 확인·불필요한 권한 질문·완료한 작업의 재시작을 싫어한다. 이미 선택한 시안/기기 범위/배포 대상을 다시 묻지 않는다. 새롭고 중요한 미정 선택만 확인한다.
- 사용자가 중간에 질문하면 짧게 답하고 현재 목표를 이어간다. ‘대답만’이면 도구 실행/개발을 진행하지 않는다. 영상들을 모두 보내기 전에는 요청대로 수신 답변만 한다.
- 디자인 시안 먼저 요청한 변경은 시안→선택→구현 순서로 한다. 시안이 안 보인다고 하면 실제 보이는 이미지/링크를 제공한다. 코딩 완료를 시안 확인으로 대신하지 않는다.
- Duo/일반 iPhone의 새로운 상호작용 범위는 각각 설명한다. 이미 확정한 카메라 열·반대 pane·일반폰 하단 탭은 반복 재질문 없이 보존한다.
- ‘빌드’라는 말은 문맥으로 웹 배포/IPA를 구분한다. 상태 보고에는 커밋·CI·Render·IPA·Apple 처리·사용자 설치를 나눠 적는다.
- ‘내일 물어보면’은 사용자가 다시 물을 때 이어 안내하라는 뜻이다. 자동 예약/알림 생성 지시로 확대하지 않는다.
- 외부 메일/Slack 메시지 발송은 별도 명시 요청 범위에서만 한다. 문서화 때문에 타인에게 통지하지 않는다.

## 3. 제품 목표와 범위

### 3.1 무엇을 만드는가

개인·생활·업무 자료를 받아 맥락을 이해하고, 채팅에서 정리·완료하거나 Todo/캘린더로 옮길 수 있는 지속적인 AI 비서다. 사용자는 Dots의 수신·장기 기억·위임·후속 작업 등 공개 전체 기능을 지향했다. 단순 하루 요약 또는 ChatGPT 설정 복사로 축소하면 안 된다.

긴 작업·중간 승인·대기·재개·반복 책임·문서 읽기/작성·분석·코드·컴퓨터·여러 채널 경로가 저장소에 있다. 그러나 경로 존재를 Dots와의 완전 동등성, 실제 계정 등록 또는 모델 품질 성공으로 표현하지 않는다. [Dots 계약](dots-parity-2026-11-15.md), [설정 경계](dots-full-setup-2026-11-15.md)를 확인한다.

### 3.2 다른 AI/GPT 연결의 의미

사용자가 ChatGPT/Dots를 연결해 결과를 docen에 받아 Todo처럼 보여주는 방안을 제안했다. 이는 아이디어/후속 통합 과제다. ChatGPT 구독이나 로그인만으로 기존 대화·장기 기억·Dots 결과를 읽거나 API 사용료가 공유되지 않는다. 공식 도구/MCP 등 선택 전송 경로·상용 등록·권한·실계정 검증이 필요하다. 자동 Dots 가져오기가 현재 제공되는 것처럼 소개하지 않는다.

### 3.3 현재 제작 우선순위

소개 웹 공개 준비 + 앱/웹의 안정성·사용성 + 실제 가입/인증 + 운영 어드민. 데스크톱 네이티브 다운로드, Mac App Store, 전화 기능, AI 사무실은 별도 후속 범위다. 미리알림이 필요하다는 이유로 웹이 EventKit을 직접 호출할 수 있다고 설명하지 않는다.

## 4. 브랜드·식별자·약관

- 모든 현재 표시 이름은 docen. 한국어/영문 소개·title/meta·AI 기본 이름·메일 제목·푸시·ME·어드민·내보내기 표시를 같이 관리한다.
- 오리 마스코트는 유지한다. 사용자 작성 대화/문서/사용자 지정 비서 이름을 일괄 치환하지 않는다. 과거 기본 이름만 읽기 시 정규화하며 암호화 원문을 덮지 않는다.
- Apple bundle com.sjfieni.duckduck, Expo project/slug, duckduck:// scheme, OAuth callback, 쿠키/SecureStore key, DB 파일/암호화 salt, protocol/export format 식별자는 기존 계정·로그인·서명을 보존하기 위해 유지한다.
- 약관 정본은 server/legal-policy.js·server/legal-content.js다. 현재 버전2026-11-22.2, 이용약관·개인정보·AI·쿠키 4종이다. 기존2026-11-22 및.1 고정 문서와 과거 동의 기록은 보존한다.
- 단순 이름 변경과 법적 운영자 변경은 다르다. 이름 변경 시 신규 문서 버전·변경 사실/적용일 안내·사이트/가입/ME 표시를 함께 갱신한다.
- 법적 운영자/공개 문의는 기존 확인된 값으로 유지한다. 비공개 운영자 계정/개인 페이지를 공개 자료에 추가하지 않는다.
- 개인정보 국외 처리 수탁사의 실제 국가·법인·연락처·보관/계약 조건의 미확정 항목은 확인 필요다. App Store metadata의 최종 검토 미완료를 해소한 것처럼 쓰지 않는다.

## 5. 디자인 원칙 — 외형보다 정보와 흐름

- 기본 방향: 간결한 목록→상세. 한 화면에 큰 설명 카드·중복 제목·동일 설정 진입을 반복하지 않는다.
- Things는 Todo 밀도·날짜별 흐름·인라인 편집·부드러운 이동의 참고다. 사용자 제공 Things/피클 녹화는 오류 영상이 아니라 UX/UI 참고다.
- Any.do는 현재 소개 사이트의 섹션 뼈대 참고다. 내용은 docen 자체 내용이며 **현재 소개에는 영상 제외**다. 과거 피클 영상형 사이트가 최신 기준은 아니다.
- 홈페이지 배경/색/간격/반응형과 어드민의 정확한 수치는 [제작 매뉴얼](docen-product-build-playbook.md)을 읽는다. 예전 reference.css에 코드가 남았다고 현재 화면에 사용한다고 추정하지 않는다.
- 앱 공통 토큰 원본은 mobile/src/theme.ts. 일반 간격4/8/12/16/24/32, 앱 기본본문17/25.5·목록16/24·보조13/19.5 기준이나 특정 Todo 최신 compact 행은 분야별 계약 우선이다.
- 기능 차이를 색만으로 전달하지 않는다. 실제 터치 영역·큰 글자·스크린리더·동작 줄이기를 고려한다. 웹 대체 Glass와 native 광학 효과는 구별한다.
- Glass는 내비게이션/조작부에 제한한다. 본문·목록 전체에 반투명/가짜 무늬를 넣지 않는다. 동작 중 초안·스크롤·선택일을 보존한다.

## 6. 앱·Duo·웹을 서로 구분하기

### 6.1 일반 iPhone

기술 탭 ID 순서는 calendar/todos/duck/log/profile이다. 표시 이름은 현재 docen 브랜딩을 따른다. 일반폰은 기존 떠 있는 둥근 하단5탭을 유지한다. Duo에서 헤더를 없앤다는 요청을 일반폰에 그대로 적용하지 않는다. 일반형 확인은 웹으로 하기로 했으며 앱 내부 ‘일반 iPhone 미리보기 전환’을 임의 추가하지 않는다.

### 6.2 Duo의 확정 공간

물리 카메라가 있는 맨 오른쪽 열 아래 세로5탭. 본문 오른쪽 끝/별도 가짜 padding 열로 옮기지 않는다. 기존 계약의 바64×272pt·아이콘28pt·터치52pt·상하 안전8pt를 기준으로 실제 코드와 대조한다. 접힘/펼침/회전에도 유지한다.

펼친 가로는 왼쪽 Calendar 고정, 오른쪽 최초 Todo이며 탭은 오른쪽만 바뀐다. 세로/접힘은 선택한 한 화면을 본문 전체에 표시한다. 실제 pane gutter 중앙 얇은 분할선은 가로 두 pane에서만, 실제 힌지/가림과 충돌하면 생략한다. 가짜 카메라를 제품에 그리지 않는다.

사용자가 추가 공간 확보를 요청해 **Duo의 맨 위 장식 오리와 헤더 높이를 제거**했다. 일반폰 헤더는 유지한다. OS 공식 API에 근거하며 화면폭/모델명만으로 iPad·일반폰을 Duo로 판단하지 않는다. 기하 fixture는 실제 하드웨어 지원 검증이 아니다.

### 6.3 웹 작업공간

사용자는 앱 복제 대신 **소개 상단 ‘나의 하루’ 포맷**을 원했다. web·비Duo /app은 폭과 관계없이 웹 작업공간이다. 최대1128px 프레임·상단54px·좌171px·우245px, 중앙 브리핑/Todo/캘린더/log/ME. 1100px 미만 오른쪽 접힘, 760px 미만 왼쪽 메뉴는 상단 가로로 전환한다. 실제 native 탭 배치를 바꾸는 지시가 아니다.

브리핑 위 날씨는 숨긴다. 왼쪽에는5개 상위 메뉴만 두고 ME 하위 연결/예약 바로가기를 상시 노출하지 않는다. 기능·저장 자료·알림 설정 삭제와 화면 숨김을 구분한다.

## 7. Todo 계약

- 직접 작성 영역이 먼저 온다. 날짜별/출처별 전환을 제공한다. 날짜별은 큰 날짜·요일·구분선 아래 일정과 Todo, 출처별은 실제 Slack/Google Tasks/미리알림 등으로 묶는다.
- 제목이 먼저 읽히고 날짜·실제 출처는 보조 줄로 표시한다. 확인된 원본 링크만 제공한다. Apple 미리알림 deep link를 추측해 만들지 않는다.
- 긴 누르기/다중 선택 이동과 대체 위·아래 버튼을 제공한다. 날짜별 이동은 예정일 편집 및 원본 전파 경로를 사용한다. 출처별 순서 변경은 같은 공급자 그룹 안의 순서만 바꾸며 출처를 변조하지 않는다.
- 행 높이는 초기60pt→Things형48pt→사용자 영상 적용 compact44pt 등 이력이 있다. 새 수정은 최신 reference-flows와 실제 컴포넌트를 대조한다. 긴 글자/글자 확대에서는 자연스럽게 확장한다.
- 기본 메모 최대4,000자·최소220pt. 최신 compact inline 메모만72~160pt 내부 스크롤 예외다. 한글 IME/줄바꿈/커서/초안 보존을 지킨다.
- 완료/복원은 즉시 표시하고3→2→1 각1초, 그 뒤 약350ms 페이드/접힘. 0은 표시하지 않는다. 동작 줄이기에서는 시각 모션을 줄이되 되돌리기 시간은 유지한다. 완료 기록은 log, 원본의 완료 기록은 참고용이며 새 Todo로 가져오지 않는다.
- Todo 탭을 다시 누르면 맨 위로 올라간다. 열린 편집/드래그/초안을 버리지 않는다.
- 프로젝트/영역/소제목 구성은 조사·제안 문서가 있으나 Todo 프로젝트 관리 출시가 확정된 것은 아니다. 채팅 업무 소제목 구현과 구분한다.

## 8. 캘린더 계약

- 월간42칸, 월/주/일/목록·선택일·상세·편집·검색·소스 선택·년월/연간 탐색 이력은 유지한다. 월±1월/주±7일/일±1일의 의미를 섞지 않는다.
- 첫 주의 위 구분선은 **당월1일부터** 시작한다. 이전달29/30일 위까지 선을 그리지 않는다.
- 최신 승인한 주간은 두 주를 채우는 보기. 주간을 다시 누르면 선택일 일간, 다시 누르면 월간으로 돌아간다. 7개 긴 열의 별도 시안은 보류다.
- 주간은 일정+미완료 Todo를 끝까지 보여주고 +N으로 숨기지 않는다. 행이 늘어나며 기존 한 스크롤 안에서 아래 내용까지 본다. 월간의 정보량 설정과 혼동하지 않는다.
- 마지막 선택 소스/표시 snapshot을 먼저 복원하고 즉시 배경 갱신한다. 범위가 달라도 겹치는 저장분은 먼저 보이며 늦거나 실패한 갱신이 이미 보이는 내용을 비우지 않는다. 소스별 도착부터 반영한다.
- cache는 계정/서버/시간대/연결 경계를 지킨다. 표시 snapshot을 최신 ETag/쓰기 권한의 증거로 사용하지 않는다. 계정 전환/해제 시 제거한다.
- 읽기 전용 원본도 로컬 편집 초안은 쓸 수 있지만 실제 원본 저장 가능 여부와 권한·동기화 상태는 분명히 보여준다. 원본 권한 없는 편집을 저장 성공으로 표시하지 않는다.

## 9. AI 채팅·브리핑·기억

### 9.1 입력과 실패

AI 상태를 조회 중이거나 연결이 실패해도 같은 채팅 입력창을 유지한다. 입력한 글을 자동 Todo 작성으로 바꾸지 않는다. 사용자는 ‘글자는 써지지만 전송 버튼이 작동하지 않음’이라고 명확히 설명했다. 입력 가림과 전송 실패를 별개로 재현한다.

첫 화면의 오늘 내용 보기/비서/기록 찾기/대화 붙여넣기 도구는 후속 요청 전 숨긴다. 전화 진입도 숨긴다. 첨부는 입력창＋의 기존 경로를 유지한다. 숨김을 기능/기록 삭제로 바꾸지 않는다.

전송 상태/오류는 입력 바로 위에, 실패한 입력/첨부/동의는 보존하고 사용자가 재전송할 수 있게 한다. 서버 오류를 단순 ‘느리다’로 확정하지 않는다. 읽기 GET의 한정 재시도와 쓰기/발송 중복 실행 금지는 구별한다.

### 9.2 브리핑이 할 일로 연결되는 방식

시간 제목→업무 소제목→체크 행→짧은 설명·날짜·출처 링크. 긴 원문/보고서는 펼쳐 읽는다. 체크는 완료/log, 오른쪽/메뉴 Todo는 보관, 왼쪽/메뉴 캘린더는 일정초안→날짜/시간/대상 확인→한 번 저장이다. 제외는 후보 숨김이지 원본 삭제가 아니다.

원본 ref+업무의 안정 키·소유자 기준으로 완료/Todo/캘린더/제외 처리 이력을 보관해 다음 브리핑의 새 후보에서 빼야 한다. 같은 원문에서 나온 독립 후속 업무는 남긴다. 같은 일을 표현만 바꾸면 언제나 완벽하게 탐지한다는 보장은 하지 않는다. 저장된 과거 대화를 지우는 방식으로 해결하지 않는다.

### 9.3 기본 설정과 동의

최초 브리핑 프리셋은 평일9–18시 매시·중요 변화·연결 읽기 자료·알림 ON이라는 최신 사용자 지시가 있다. **이미 저장한 OFF·선택 소스·OS 거절·이메일 인증·반복 AI 자료 사용 동의·복구 후 중지 상태는 존중**한다. 제품 기본 ON과 OS 권한/실제 발송 동의는 같은 뜻이 아니다. 무료1회/일 제안은 현재 웹 표의 Free 포함 기능과 다르므로 자동 출시 정책으로 적용하지 않는다.

현재 웹 브리핑 화면에서 날씨를 숨기는 요청은 별개다. 모든 날씨 예약/원문 삭제·사용자 설정 강제 OFF로 해석하지 않는다.

### 9.4 장기 기억·지속 작업

명시 opt-in 이후 대화·확인한 사실·작업 메모를 암호화 저장/검색한다. 편집/잊기/전체 삭제/내보내기를 제공한다. 외부 문서의 지시를 사용자 명령이나 기억으로 승격하지 않는다. 기억 OFF에서도 최소 처리 이력은 별도 근거로 동작하고 전체 대화를 몰래 저장하지 않는다.

초기 기억 계약의500개/항목1,000자·최근24개 문맥·화면40turn·과거2,000개 검색과 이후 관련 검색 확장을 혼동하지 않는다. 한도를 바꾸기 전 실제 구현/해당 최신 계약을 조회한다. 무한 기억 또는 ChatGPT 기억 공유를 약속하지 않는다.

지속 작업은 checkpoint·동시 지시·승인/대기/재개·연결/동의 개정 검사를 유지한다. 연구는 읽기 전용, 외부 쓰기는 확인 또는 정확한 대상/기간의 승인 규칙만 허용한다. 복구 후 작업/예약/채널/컴퓨터/통화를 자동 재개하지 않는다.

## 10. 원본 동기화·미리알림·빠른 저장

### 10.1 사용자에게 보이는 결과

저장을 누르면 화면에서 먼저 바뀌고 내부 저장을 진행한다. 저장 중/원본 반영 중/확정/실패/결과 확인 중을 구별한다. **확정 거절**은 마지막 확인 값으로 되돌리고 이유·대안을 채팅에 남긴다. 응답이 끊겼다는 사실만으로 미저장이라고 판단해 무조건 되돌리거나 재전송하지 않는다.

새 Todo는 계정별 요청 ID로 멱등 생성한다. 내용 수정의 응답 유실은 대상 읽기와 필드 비교, 외부 일정은 기존 action ID 상태 조회로 확인한다. 늦은 응답/계정 전환 결과가 최신 편집을 덮지 않는다.

### 10.2 서버와 원본 쓰기

Google 변경은 docen 저장+암호화된 원본 대기 작업을 같은 트랜잭션으로 기록하고 queued로 반환한다. 아직 보내지 않은 변경은 합치며 실행 중/unknown은 보존한다. 실행 ID를 먼저 기록하고 사용자·권한·ETag·동의·최신 개정을 재검사한다. 임대 만료 후에도 같은 결과를 읽고 새 쓰기를 중복 전송하지 않는다. 미해결 unknown은 후속 원본 쓰기도 막는다. 완료 기록 정리와 unknown 보존을 구분한다.

‘모든 원본에도 같게’는 제품 목표다. 공급자마다 지원 필드가 다르다. Calendar에는 Todo 완료를 삭제로 대신하지 않는다. Google Tasks 예정일의 공급자 시간 의미를 임의 확장하지 않는다. Naver 읽기 전용/Slack 자기 메시지 범위 같은 제한을 숨기지 않는다. 불가/충돌/권한 거절 시 채팅에서 원본 앱 열기·재연결·docen 임시 보관·기기에서 재시도 등 실행 가능한 대안을 준다.

### 10.3 iPhone 미리알림

모든 접근 가능한 목록의 **미완료만 전체 가져오기**. 날짜 없음/지난 기한도 포함한다. 화면50개 렌더나 요청20개 제한이 전체 가져오기 수 제한이 되어서는 안 된다. 20개·256KB 요청 제한 안에서 나눠 전송하고 진행/추가/기존/실패 목록을 표시한다. 이어 가져오기는 원본 ID로 중복 방지한다. 완료 이력은 참고 전용이다.

docen의 체크/복원/내용·날짜·시간 수정은 해당 가져온 기기의 EventKit 경로로 원본을 바꾸고 readback과 현재 개정으로 성공을 확인한다. 웹/서버가 OS 권한을 대신 행사하지 않는다. `CALENDARWRITEONLY` 오류는 SDK58의 event-scoped 경로 문제로 조사/수정했으며 reminder-scoped 목록/읽기 경로를 유지한다. 권한 실패에 캘린더 전체 권한을 무작정 요구하지 않는다.

### 10.4 느림 원인과 한계

실제 조사 이력에는 libSQL 동기 HTTP가 Node loop를 막던 문제·반복 metadata 조회·첫 권한 목록 객체/빈 응답·비JSON 응답·OpenAI 잔액429가 있다. 모든 화면 오류가 같은 원인이라는 결론은 아니다.

기존 무료 Render 프로세스 내부에서 gateway와 기본/auth lane·외부/비서 lane을 worker thread로 나눴다. 유료 별도 Render worker/Redis를 새로 만든 것이 아니다. 동일 lane 지연·provider 장애·Free cold start는 남는다. 마지막 캐시와 빠른 피드백은 지연을 숨기는 허위 성공이 아니라 상태를 보여주는 구조다. 무지연/무오류/24시간 SLA를 약속하지 않는다.

## 12. 회원가입·로그인·세션

- 일반 회원은 이메일+비밀번호다. Google/Apple 로그인은 별도 미구현이며 자료 연결 OAuth와 다르다.
- 새 비밀번호8~128자, 숫자+공백 아닌 ASCII 특수문자 포함, 영문/대소문자 의무 임의 추가 없음. 확인 입력 두 칸, 기준은 첫 칸 아래, 불일치는 두 번째 빨간 테두리+아래 문구, 첫 칸 규칙 위반도 빨간 테두리/outline이다.
- 서버도 passwordConfirmation과 동일 정책을 검사한다. 기존 계정 로그인/삭제에는 새 생성 조합을 강제하지 않는다. 관리자 비밀번호 정책은 별도이므로 일괄 변경하지 않는다.
- 약관·개인정보의 현재 버전과 만14세이상 확인을 요구한다. 사전 체크 없음, 마케팅/외부 연결/AI 동의를 필수 가입 동의에 묶지 않는다. 실제 동의 기록을 트랜잭션 저장하며 과거 회원 동의를 허위 생성하지 않는다.
- 가입 직후 인증 메일 자동 요청. 인증 전 제한 세션에서는 인증 화면만 보이고 내부 메뉴/자료를 로드하지 않는다. 서버는 최소 계정/session·send/confirm·logout 이외 API를403 EMAIL_VERIFICATION_REQUIRED로 막는다. 재로그인/새로고침/기존 미인증 세션도 동일하다.
- 인증번호6자리·15분·최대5회·재전송60초/시간당5건. 재발송은 이전 번호를 무효화한다. 영구 발송 거절은 코드/대기 본문을 폐기하고 고정 실패 분류만 남긴다.
- 웹 HttpOnly/Secure/SameSite Strict 쿠키·30일 세션, native SecureStore. 지연·네트워크 실패를401처럼 로그아웃 처리하지 않는다. 오래 안 켰다가 열 때 세션 복원 중 전용 상태와 내비게이션 자리를 유지한다. 인증 안 됐는데 내부 데이터가 잠깐 보이는 것도 금지다.
- 비밀번호 재설정은 같은 새 비밀번호/확인 정책, 성공 시 기존 세션 폐기. 계정 삭제는 현재 비밀번호·명시 확인과 실제 자료/동의/연결 정리를 따른다.

## 13. 어드민 — PG 이외 실제 운영 연결

자세한 파일·CSS·API 제작 순서는 [제작 매뉴얼](docen-product-build-playbook.md)의 어드민 절을 읽는다.

- 왼쪽 메뉴를 누르면 오른쪽 내용이 바뀌는 운영 화면. 먼저 사람을 검색하고 회원ID/인증/가입/이용권/연결/AI 사용 상태를 회원별로 본다.
- 관리자와 일반 제품 계정은 완전히 별개 테이블·비밀번호·세션이다. 사용자 지정 총관리자 주소는 서버 allowlist에만 보관한다. 테스트용 제품 계정을 총관리자로 오인하지 않는다.
- /admin 로그인 전에는 로그인 카드만 표시한다. sidebar·빈 대시보드·이전 회원 캐시도 그리지 않는다. 공개 admin-preview는 /admin으로 보내고 예시JS 노출 경로를 닫는다.
- 사용자가 지정한 초기 임시 비밀번호로 1회 준비하고 첫 로그인 후 즉시 변경만 허용한 최신 정책이 있다. 값은 절대로 문서에 쓰지 않는다. 서버 DUCK_ADMIN_INITIAL_PASSWORD 보안 설정으로만 취급한다. 재시작으로 재초기화하지 않는다.
- 총관리자/운영자/조회 전용. 총관리자만 운영자 등록·역할/접근 변경. 본인 총관리자 강등/차단 보호. 서버가 매 요청 권한을 확인한다.
- 수동 Free/Lite/Pro 발급·변경·회수·만료, 회원 정지/해제·모든 세션 종료, 연결 점검·읽기 갱신·실패 작업의 제한 재시도, 감사 기록을 실제 연결했다. 이를 단순 뼈대로 되돌리지 않는다.
- 모든 변경에 사유·요청ID·대상버전, 변경/감사/멱등 영수증을 한 트랜잭션으로 저장한다. 같은 요청 재전송은 동일 결과, 충돌409, 이미 성공/진행/unknown인 원본 작업은 재실행하지 않는다.
- 수동 이용권은 실제 결제가 아니고 AI 예산을 만들지 않는다. PG/구독/환불/정산은 미구현이다. 결제 날짜/매출은 실제 거래가 있을 때만 표시한다. 가상 데이터를 매출로 세지 않는다.
- 어드민에는 원본 본문·대화·토큰·비밀번호·세션을 노출하지 않는다. 단순 조회도 권한/감사 대상이다. 연결 점검 성공과 전체 자료 동기화 완료를 구분한다.
- 새 docen.today에서는 /admin도 서비스 미오픈 guard로 차단된다. 기존 테스트 host에서만 기존 경로를 유지한다.

## 16. 오늘 진행한 Resend·HostingKR·Render 상세 기록

### 16.1 메일: 완료와 근거

이전 팀에 다른 서비스가 있을 수 있어 사용자가 새 Resend 계정을 선택했다. 같은 팀은 도메인/API키별로 무료 쿼터가 분리되지 않는다. 새 팀의 실제 quota/가격은 계정/공식 정책으로 재확인한다. free3,000월/100일 등의 당시 확인값을 영구 정책으로 보장하지 않는다.

새 팀 표시 herryk153, 도메인docen.today, Tokyo, Sending ON. 사용자가 TXT DKIM·CNAME rsend/send·TXT DMARC를 직접 등록했다. Resend 화면에 domain Verified/Forge Ready·sending records Verified를 제공했다.

| 유형 | 호스트 | 값/참조 | 보존 |
|---|---|---|---|
|TXT|resend._domainkey|Resend가 발급한 전체 공개 DKIM값. 현재 콘솔/저장 레코드에서 확인|재발급/줄임 복사 금지|
|CNAME|rsend|rsend-apne1.forge.rmta.net|웹DNS와 별개|

사용자가 API Keys에서 Name docen-production / Sending access / Domain docen.today로 키를 발급했다. 키는 AI에게 전달하지 않고 Render Environment의 MAIL_API_KEY에 직접 입력, MAIL_FROM은 docen <no-reply@docen.today>로 설정했다고 완료했다. 서버 배포dep-dc1fbe9ksfps738ojumg·15a34d247694af4122bd9b87978f0c85515a373c·14:02:24.829319Z live를 도구로 확인했다. 이후 소개 전용 배포로 대체됐다.

사용자가 실제 인증메일 수신/번호 입력/내부 진입 질문에ㅇㄹ로 완료 확인했다. 발송 설정 존재/큐 접수202/공급자 수락/실제 수신은 각각 별개이며 이번에는 마지막 단계의 사용자 확인이 있다. Sending access키의 GET/domains401 restricted-api-key는 조회 권한 제한일 수 있고 발송 실패 증거가 아니다.

### 16.2 사이트 DNS: 저장 확인, 인증/TLS 미완료

Render Settings→Custom Domains에docen.today와www.docen.today가 사용자 화면으로 등록됐다. www는 루트로 redirect하는 구성이다. 도메인 안내에는 root의A대체값216.24.57.1이 명시돼 있다.

| 유형 | 호스트 | 값 | TTL |
|---|---|---|---:|
|A|@|216.24.57.1|180초|
|CNAME|www|duckduck-test.onrender.com|180초|

사용자가 저장 목록 캡처로 두 레코드와값을 확인시켰다. 잘못 입력했다고 단정하거나 CNAME@로 다시 바꾸거나 메일 레코드를 삭제하지 않는다.

확인 과정: 공개 Google DNS over HTTPS의 /resolve?name=docen.today&type=A 및 www의CNAME을 읽기 전용 조회했다. 초기에는 두 응답에Answer가 없었고 다른 조회의SOA serial5/7이 혼재했다. 마지막 조회는 www CNAME→duckduck-test.onrender.com. /TTL180이 응답했지만 루트A는SOA serial5의Authority만 있었다. 이는 일부 반영/서버간 전파 또는 캐시 차이와 일치하나 원인 전체가 확정된 것은 아니다. 당시 AAAA/CAA 응답에는Answer가 없었으므로 충돌 증거 없이 삭제하라고 하지 않는다.

다음 단계: 5~10분 뒤 Render 안내창 닫기→각 도메인 오른쪽↻→Verified 확인→Certificate상태 확인→https://docen.today 및www redirect실접속. 지연 지속 시 동일 레코드 반복 추가보다 authoritative NS별 응답/HostingKR저장/NS위임/충돌을 조사한다. ‘24시간 기다리면 무조건 된다’고 말하지 않는다.

TinyFish 원격 브라우저는 모바일에서 터치/스크롤이 작동하지 않아 사용자가 중단하고 직접 진행했다. 같은 재로그인을 반복 요구하지 않는다. 공개 DNS의 passive fetch와 로그인/원격 조작은 구분한다. 실행환경/검색 도구 접근 실패를 운영 사이트 장애로 단정하지 않는다.

### 16.3 공개 웹을 열 때 별도 전환

지금 PUBLIC_ORIGIN·native API·Google/Slack callback을 새 도메인으로 변경하지 않는다. docen.today 소개 전용 guard를 유지한다. 추후 서비스 오픈 지시가 오면 프런트 CTA/서버 host+Origin guard/CORS·cookie/OAuth등록·메일링크/기존 native호환을 같이 검토·테스트한다. DNS 성공은 이 출시 승인을 대신하지 않는다.

## 17. 테스트·빌드·배포 방법

일반 절차: 상태/지침→관련 계약/테스트→작은 구현→관련 검사→의미 있는 회귀→Git 기록→필요 시 배포→실제 상태 확인→문서 갱신. 사용자 변경을 덮거나 실패 테스트를 삭제하지 않는다.

```sh
node --version
npm ci
npm run check
npm test
npm --prefix mobile run typecheck
npm --prefix mobile run export:web
npm --prefix mobile run export:ios
npm --prefix website run build
npm --prefix website run test:sites
python3 scripts/build-handoff.py
```

명령은 해당 의존성/실행환경을 준비한 뒤 관련 범위에 맞게 실행한다. 문서만 바뀐 경우 앱 전체 빌드/서명/유료AI를 불필요하게 반복하지 않는다. 홈페이지 상호작용검사는 website/tests/interaction.mjs, 소개 미오픈 브라우저 검사는 website/tests/public-launch.mjs, 서버 guard검사는 test/public-launch.test.js를 읽는다.

현재 소개 배포 당시 전체465중464통과/기존1skip/실패0, 문법123개·사이트build/4tests·실제PC390px/KR·EN/QR·가격/합성예시·새hostguard를 검증했다. 이 숫자는 그 배포 기록이며 이번 문서 작업에서 다시 전부 실행했다고 하지 않는다.

Render 자동배포는off. Gitpush와live는 별개다. 기존 무료 서비스에서 정확한소스SHA/배포ID/완료시간/health/실제 페이지를 기록한다. 새host의DNS/TLS는 별도다.

iOS는 공개GitHub의 무료Mac·xcode-27/Xcode27.1·EAS local --freeze-credentials→같은IPA제출, workflow_dispatch수동이 기준이다. push로TestFlight자동실행하지 않는다. 실패run Re-run은옛소스일 수 있으므로 최신main의새실행을 쓴다. Expo cloud할당량/유료runner로우회하지 않는다. GitHub권한거절은컴파일실패와다르다. 사용자 ‘빌드’ 요청범위가 없는데 문서정리때native를새로실행하지 않는다.

## 18. 기록·노션·전달물 관리

저장소 기술문서가 실제 파일 정본이다. 예전에 선택된 개인 Notion의제품기록을 사용하자는 규칙이 있으나, 이번 세션에서 최신내용을Notion에저장한증거는없다. 공개 기술문서+import파일 존재를Notion저장완료로말하지않는다. 개인Notion계정/대상을확인하고실제로접근할수있을때별도동기화한다. 다른사람의워크스페이스에임의생성하지않는다.

notion-handoff.md와public/project.html은scripts/build-handoff.py생성물이다. 생성물만직접고치지않는다. 이번통합문서·결정목록·매뉴얼·지도도생성기에서포함해한번에전달할수있게한다. 제공ZIP/오프라인HTML에는키·DB·세션·node_modules·비공개페이지/사용자원본을넣지않는다. 공개프로젝트페이지는운영자전용자료함이아니므로계정주소/비밀운영정보를추가하지않는다.

새AI에게줄때이문서하나만으로현상황을읽고,실제수정에는저장소와분야별계약을함께전달한다. 상세지도는문서전체경로와첫제목을제공한다. 미래작업마다요청/결정/이유/파일/검증/배포/미확인/다음단계를보충한다.
