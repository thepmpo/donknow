# 관리자 인증메일 발송 실패 진단

## 관측

사용자의실패신고시점에운영POST가503/약1초로실패했다. 기존메일러는Resend거절을모두일반Error로만들고관리자라우트도구체사유를삭제했다. public mail:true는키/발신값존재를뜻하며성공발송증거가아니다. 실제키/도메인상태는아직확인중이다.

## 변경

메일키/발신값의앞뒤공백을정리하고고정HTTPS메일endpoint/동일idempotency/redirect:error를사용한다. 실패응답은8KiB까지만메모리에서읽어고정enum(테스트수신자제한,발신도메인미인증,키인증/권한,발송제한,업체/네트워크)으로변환한다. 원문메시지/키/주소/인증번호/본문은로그나프런트에전달하지않는다. 관리자실패시코드는기존대로폐기하고이유별정제된안내를준다.

운영startup에서메일발송없이GET https://api.resend.com/domains를한번조회한다. 성공시현재발신도메인의상태enum만남긴다. 제한키오류는restricted-api-key로구분하며발송전용키의정상적읽기거부일수있다. 응답의도메인/키값은출력하지않고도메인을등록/변경하지않는다. 실제발송을임의재요청하지않는다.

## 검증

대상11개·전체447/446통과/실패0/기존1제외,115문법검사. 공백정리/고정endpoint/idempotency/redirect금지·403테스트수신자및도메인거절·인증/권한/한도·비밀값미노출·read-only설정조회·실패코드폐기와로그인경계를검증했다. 실제운영메일성공은별도이고진단/후속조치결과는배포후추가한다.
