# PG를 제외한 관리자 운영 기능

## 회원별 이용권과 상태

회원 검색 후 이용권 목록에서 Free/Lite/Pro를 즉시 발급하고 종료일을 지정하거나 변경·회수할 수 있다. 수동 발급 이력은 실제 시작·종료·회수 시각으로 남는다. 기존 공통 무료 Pro 정책은 개별 변경을 하지 않은 회원에게 유지된다. 개별 이용권이 회수되거나 만료되면 Free로 전환된다. 등록/로그인/기존 세션/계정 API/AI 접근은 같은 실제 정책을 읽는다. PG 거래나 AI 예산을 생성하지 않는다.

회원 정보에서 정지·해제와 모든 기기 로그아웃을 실행한다. 정지 시 세션을 폐기하고 신규 로그인을 차단한다. 예약·모니터·이벤트·에이전트·원본 작업 선택 대상에서도 제외하며 외부 실행 직전 활성 상태를 다시 검사한다. 데이터·동의·연결은 삭제하지 않는다. 이미 외부에 전송된 요청을 소급 취소한다고 주장하지 않는다.

## 운영자

서버 허용 목록의 총관리자, 별도로 등록한 일반 운영자, 조회 전용을 구분한다. 일반 운영자는 회원/이용권/연결 점검/재시도를 관리하고 조회 전용은 서버가 쓰기를 거부한다. 총관리자만 운영자 등록·역할 변경·접근 중지·초기 비밀번호 재설정을 할 수 있다. 총관리자 본인의 강등·중지는 막는다. 비밀번호 변경은 운영자 관리 화면에서 본인이 현재 비밀번호를 확인한 후 실행한다. 초기 비밀번호 로그인은 변경 화면만 허용하고 변경/역할 수정/중지/재설정 시 기존 세션을 폐기한다. 덕 앱 계정과는 독립적이다.

서버 허용 목록에서 빠진 기존 총관리자는 관리형 조회 계정으로 자동 전환되지 않는다. 역할 변경 전후 상태와 비밀번호 변경 여부만 감사에 남기며 비밀번호·세션·토큰은 저장/표시하지 않는다.

## 연결과 동기화

연결·동기화에서 Google/Slack/Notion의 고정 공식 API로 실제 인증을 점검하고 결과/시각/정제된 실패 사유를 기록한다. 연결이 바뀌면 이전 점검은 무효다. 자료 새로고침은 현재 읽기 권한의 지원 자료 첫 페이지를 실제 조회하고 기존 자료 캐시를 유지한 채 갱신한다. 다음 페이지 유무를 반환하며 전체 동기화 완료로 가장하지 않는다. 기존 동의가 있는 모니터도 깨우며 새 AI 동의·예약·쓰기 권한은 만들지 않는다. 미지원·기기 연결은 정상이라고 표시하지 않는다.

최신 실패 원본 편집만 재시도한다. 영수증이 진행 중/성공/결과 불명이거나 더 최신 수정이 있으면 재실행하지 않는다. Google Tasks는 기존 쓰기 권한·동기화 켜짐을 확인한 실패 작업만 대기열로 되돌린다. 충돌은 자동 덮어쓰지 않는다. 아이폰 미리알림은 기기 접근이 필요하므로 덕 비서에 기기 권한 확인과 원본 재시도 방법을 안내한다. 어드민에는 원본 제목·본문·대화·자격 증명이 표시되지 않는다.

## 변경 안전성과 PG 경계

모든 운영 변경은 변경 사유·요청 ID·대상 버전을 요구한다. 변경/감사/재실행 방지 영수증을 같은 DB 트랜잭션으로 커밋한다. 같은 요청 재전송은 중복 발급·재시도를 하지 않고 다른 요청이나 오래된 버전은 409로 거부한다. 비밀번호 설정은 해시만 저장하고 감사에는 변경 여부만 남긴다. HttpOnly/SameSite Strict/Secure cookie, 원본 출처 검사, CSRF 헤더, 요청 제한을 유지한다.

PG 결제·구독·환불·정산은 구현 범위 밖이다. 수동 발급을 매출로 가장하지 않고 AI 원가 예산·키·외부 권한을 자동 변경하지 않는다. 일반 메일 발신 도메인 제한도 해결된 것으로 주장하지 않는다.

## 검증

실제 Node/SQLite HTTP 테스트와 libSQL HTTP 원격 DB 테스트에서 이용권 발급/변경/회수/만료·세션 즉시 반영·정지/해제·운영자 역할·초기 비밀번호 변경·세션 폐기·총관리자 보호·중복 요청·버전 충돌·원본 영수증 보호·비밀 정보 비노출을 검증했다. 연결 점검/자료 갱신은 통제된 provider 응답으로 검사하며 실사용자의 OAuth를 대신 사용하지 않는다.

Chromium에서 총관리자 로그인→회원 찾기→이용권 발급/회수→회원 정지→운영자 등록→조회 전용 로그인/쓰기 거부→변경 기록과 390px 레이아웃을 확인했다. 합성 화면 증거는 artifacts/admin-management-2026-11-22/에 있다. 기존 성능 검사도 채팅 상태 3개 DB 문장, 캘린더 50행 9개 DB 문장으로 유지한다.
