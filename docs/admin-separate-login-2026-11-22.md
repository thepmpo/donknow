# 별도 어드민 계정과 로그인 게이트

사용자는 어드민 주소와 덕 운영 테스트 주소가 서로 다른 계정이라고 정정했다. 따라서 관리자 이메일을덕 users에가입시키거나앱비밀번호/권한을수정하지않는다. 실제허용주소는서버전용DUCK_ADMIN_EMAILS에있으며공개문서에는값을기록하지않는다.

## 첫 설정과 로그인

/admin 접속→처음 설정·비밀번호 재설정→관리자 아이디(이메일) 입력→인증번호 받기→메일의6자리번호와새관리자비밀번호/확인입력→설정하고로그인한다. 이후에는관리자아이디/전용비밀번호로들어간다. 관리자와덕앱비밀번호/세션은독립적이다.

관리자허용환경의주소에대해startup에서admin_accounts에pending레코드를준비한다. 비밀번호/verified_at없이는로그인이불가능하다. 설정메일은사용자가화면버튼을눌렀을때만기존메일러로발송한다. 운영계정에대리로그인하거나임시암호를배포하지않는다. 메일설정public readiness는true였지만실제발송/메일열람은사용자가수행한다.

## 인증 경계

- admin_accounts는users와다른테이블이며고유관리자UUID·salt/scrypt비밀번호·메일인증시각을가진다.
- admin_operator_sessions의별도토큰해시와duckduck_admin_session Cookie만인정한다. 덕Cookie/Bearer는관리자로인정하지않고관리자토큰도덕로그인이되지않는다.
- 관리자Cookie는HttpOnly,SameSiteStrict,production Secure이며서버8시간만료다. 클라이언트스토리지에인증/회원자료를보관하지않는다.
- 설정코드는10분,5회실패한도,60초재요청제한이다. 6자리원문은DB에저장하지않고기존secretBox의HMAC으로보관한다. 메일실패면해당delivery코드를폐기한다. 잘못된주소는등록여부를드러내지않는일반응답을준다.
- 설정/재설정성공은코드1회소비와관리자세션폐기/새세션생성을한transaction으로처리한다. 덕계정/세션은변경하지않는다.
- auth POST는기존Origin/X-Duckduck-Client검사와IP요청제한을거친다. 운영자료GET은별도세션과정확한허용관리자이메일을매번검사한다. 그외쓰기405/미인증401이다.

## 로그인 전 화면

공개/admin HTML에는로그인게이트만있고사이드바/내부목록HTML이없다. 관리자세션인증성공후JS가작업공간을그린다. 로그아웃/401/403/bfcache복원에서자료와내부메뉴를지우며지연응답을버린다. /admin-preview는/admin으로302이고이전preview.js공개매핑은없앴다. 소스·기술문서의과거합성시안은역사이며실운영회원정보가아니다.

## 자료와 감사

실제회원/이용권정책/연결메타데이터/사용량의조회전용범위는이전admin-live문서와같다. 결제PG는미연결이며꾸미지않는다. 새감사는admin_operator_access_log에서관리자테이블을참조한다. 이전admin_access_log는삭제/재해석하지않고identity=legacy-duck로병합조회한다. 두감사모두회원삭제시대상ID는SET NULL이며관리자계정은덕회원삭제로영향받지않는다.

## 검사

전체443/442통과/실패0/기존1제외,114문법+관리자JS문법. targeted admin API/store3개는초대가덕가입자를만들지않음/덕비밀번호와세션불변/역할간Cookie·Bearer거부/코드1회·5회/재요청·재설정/감사와삭제·재시작/메타데이터만·페이지·조회전용을검증한다.

실제격리Node/SQLite+Chromium은덕로그인Cookie가있어도관리자로그인카드만표시하고nav=0임을확인했다. 관리자전용메일은test-outbox에서검증하고새비밀번호설정/실제관리자Cookie/회원조회·메뉴·기존덕세션유지·로그아웃중지연결과폐기·일반덕아이디거부·관리자재로그인까지검사했다. /admin-preview redirect와기본HTML에nav없음도검사했다. 실제사용자이메일/비밀번호/자료·공급자/모델호출은사용하지않았다.

artifacts/admin-separate-login-2026-11-22에캡처/results와배포후receipt를보관한다. 실제운영자는처음설정에서본인메일인증과비밀번호등록을수행해야한다.

### 로그인 입력창 즉시 표시

공개서버의첫권한확인이늦어질때입력창까지늦게보이는것을방지하기위해로그인폼은초기HTML에포함한다. 내부메뉴는여전히포함하지않으며인증성공때만그린다. 늦은401이작성중아이디를지우지않게하고새로그인/설정과세대가다른권한확인결과는무시한다. 별도브라우저지연응답과초기HTML폼존재를검수했다.
