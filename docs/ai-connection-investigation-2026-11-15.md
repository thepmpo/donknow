2026-11-15 운영 서버에서 Responses 요청이 **HTTP429 `credit_balance_exhausted`**로 거절됐다. 이 확인에 대해 API 계정 잔액/결제 설정을 확인해야 하며, 앱 재시도나 TestFlight 재빌드만으로 해결됐다고 하지 않는다. 기존 키를 출력하거나 재발급·결제·유료 자원 생성을 실행하지 않았다.

## 확인한 순서와 범위

1. 새 사진의 ‘AI 서비스에 연결하지 못했어요’는 응답 전 fetch 예외를 포괄한 경로였다. 일반 오류문에는 비밀값이 섞일 수 있어 자유 오류문/키/사용자 내용 대신 정해진 transport 코드만 기록하도록 했다. 키·모델 문자열의 앞뒤 공백을 정리한다.
2. 진단 d9410c0의 설정 모델 GET은403이었다. 이 API의 조회 권한 부족만으로 실제 추론도 불가능하다고 단정하지 않았다.
3. 사용자에게 알린 뒤43158ce/72cd426에서 개인정보 없는 짧은 정적 입력·최대16토큰·store:false로 한 번씩 최소 추론 진단했다.**72cd426** 인스턴스의13:27:59 UTC 응답에서429와 위의 허용 목록 오류 코드를 확인했다. 이때 개인 대화·문서·연결 자료를 보내지 않았다.
4. 최종 코드에서 임시 POST 진단을 제거했다. 서버 시작 때 정해진 GET 확인만 남고, 공급자의 자유 오류문·계정 정보·키는 기록하지 않는다. 실제 채팅의 잔액 오류는 한국어 원인/재시도 조건을 보여주고 가능한 경우 모델 없이 덕 채팅에도 대안을 남긴다.

HTTP429 전부를 잔액 부족으로 취급하지 않는다. 일반 속도 제한, 프로젝트/조직 한도, 인증/권한, 잘못된 모델, 타임아웃은 허용 목록으로 구분한다. 실패 요청을 자동으로 반복하거나 완료한 것처럼 표시하지 않는다. 공급자 코드 분류/transport 로그/키 비노출·재시도 금지를 검사했다. [화면·원본 저장 수정](things-source-repair-2026-11-15.md)은 이 외부 계정 문제와 별도로 구현/검증했다.

이 증거는 그 진단 요청의 잔액 실패를 확정한다. 실제 사용자 요청의 모든 과거 네트워크 실패가 동일 원인이라는 주장이나, 정상 모델 생성·실계정 문서 판단 품질 검수가 아니다. 잔액/결제 해결 뒤 실제 짧은 대화와 연결 원문 읽기를 확인해야 한다.
