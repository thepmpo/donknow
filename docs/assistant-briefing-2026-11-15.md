# Dots형 개인 비서 — 시간별 브리핑·중요 변화·문서 확인

사용자 결정: 일상부터 업무까지 돕는 AI 비서. 평일 오전9시~오후6시 매시 브리핑, 별도로 임박한 일정·기한과 나를 지정한 요청을 확인한다. 체크→완료/log, 왼쪽→X/제외만, 오른쪽→Todo다. ME에서는 연결 서비스를 한 단계 안으로 넣는다. 일반 iPhone과 Duo 접힘/펼침에 같은 자료/상태 계약을 적용하고 기존 내비게이션과 반대 캘린더를 유지한다.

## Dots 의미 정정

이전 문서가 Dots를 Pulse형 일일 브리핑으로 추정한 것은 틀렸다. [OpenAI Dots 공식 안내](https://help.openai.com/en/articles/20001530-getting-started-with-your-dot)와 [개인화 설명](https://developers.openai.com/training/walkthroughs/personalize-your-dot)에 따르면 Dots는 연결 앱, 기억, 자체 클라우드 컴퓨터, 지속적 책임과 선제적 확인/후속 작업을 가진 개인 에이전트다. [예약 작업](https://help.openai.com/en/articles/10291617-scheduled-tasks-in-chatgpt)은 그 일부와 비교할 수 있다. 덕에서 ChatGPT의 내부 Dots를 호출하거나 완전히 동일하게 구현한 것이 아니다.

| 요구 | 이번 코드의 실제 동작 | 남은 차이 |
|---|---|---|
| 매시간 정리 | daily/hourly, 평일9–18시 프리셋, 시간대/DST별 슬롯, 기존 일일 예약 유지 | 사용자 계정의 실제 설정/수신 확인 필요 |
| 미완료 누적 | 저장된 브리핑 항목과 Todo ID를 이어서 표시, 완료/X 제외 | 원본 업무 전체를 완전 수집하는 것은 아님 |
| 중요한 변화 먼저 알림 | 별도 opt-in 확인기, 실행 중 약60초 주기, 새 자료가 바뀌면 AI 요청 판별 | 공급자 이벤트/webhook 수신 미구현, 무료 서버 기동/실행 지연 가능 |
| 문서 확인 | Notion 제목 검색→중첩/페이지 이어 읽기, Drive 제목 검색→권한 있는 본문 일부 | PDF/이미지 OCR, Sheets/Slides 전체, Notion DB 질의 미지원 |
| 문서 정리 | 허용된 Notion/Drive 쓰기 초안→원본 확인→명시 실행 경로 유지 | 임의 파일/폴더 정리, 무확인 자동 원본 쓰기 미지원 |
| 기억·항상 켜진 에이전트 | 브리핑/체크 상태/변화 지문 서버 보관 | 전체 일반 대화의 지속 기억·클라우드 컴퓨터·웹 연구 미지원 |

## 연결 가능/불가능 감사

공개 운영 capability의 서버 설정을 읽어 Google/Notion/네이버 설정 있음, Slack OAuth 설정 없음을 확인했다. 이것은 **실제 사용자 계정 연결이나 AI 모델 호출 성공의 증거가 아니다**. 이 작업에 사용자 로그인 세션은 없었다. 실제 OAuth/할당량/수신 오류는 재현했다고 하지 않는다.

| 서비스 | 코드상 가능한 읽기/정리 | 실제 제한 |
|---|---|---|
| Google | 여러 계정, Gmail 본문, 기본 Calendar 일정, Tasks, Drive 이름 검색 | 승인된 기능만 사용. AI 최근 자료 수집의 Calendar는 계정별 기본 캘린더 일부임. 앱 달력 전체 목록과 다름 |
| Google 쓰기 | Calendar 생성·수정·삭제, Tasks 생성·수정/완료, Gmail 발송/답장/읽음, 앱이 접근 가능한 Drive 텍스트 생성·수정/이름 변경 | 각각의 쓰기 권한과 별도 초안/확인 필요. Drive `drive.file` 범위 밖 임의 파일 전체 쓰기 불가 |
| Drive 본문 | 일반 텍스트와 Google Docs 내보내기 일부 | `driveContent` 필요. 메타데이터 권한만 있으면 이름/설명만 읽음. PDF/Sheets/Slides를 읽었다고 답하면 안 됨 |
| Notion | 공유 승인된 페이지 검색, 하위 블록·표 행·체크 상태·페이지네이션 읽기 | 문서별 최대8회/200블록/12,000자/깊이8, 첨부·링크·DB 본문은 미확인 표시. 워크스페이스 전체 접근 아님 |
| Notion 쓰기 | 생성/덧붙이기/이름 변경 초안 | pagesWrite·공유 대상 권한·별도 실행 확인 필요 |
| Slack | 코드에 채널/메시지 읽기와 명시 쓰기 있음 | 현재 운영 OAuth 설정 없음. 연결 가능하다고 안내하면 안 됨. 전체 워크스페이스 실시간 멘션 수신도 없음 |
| 네이버 메일 | 승인한 받은편지함 일부 읽기 | 현재 read-only. 발송/답장/읽음 상태 수정 불가 |
| 아이폰 미리 알림 | native에서 선택한 미완료를 가져오기 | 서버 실시간 비서 연결·전체 지속 감시 아님 |
| 웹/다른 서비스 | 일반 모델 답변 | 웹 실시간 조사, 외부 서비스 임의 연결, 클라우드 컴퓨터 없음 |

모델과 수동 실행 목록의 `actions`는 현재 계정이 실제 승인한 기능으로 좁혔다. 잠재 카탈로그 `availableActions`와 구분한다. 선택하지 않은 서비스는 모델 실행 제안에도 넣지 않는다. 권한이 생성 도중 바뀌면409로 중단한다. 키/토큰은 모델 입력에 넣지 않는다.

## 문서 확인이 약했던 원인과 보완

기존에는 Notion 최근5개 문서의 첫 자식 페이지 내용만 읽었다. 요청 문서가 오래됐거나 중첩 내용이 있으면 찾지 못했다. Drive는 메타데이터 승인만 받으면 파일 이름만 알 수 있었다. 이번에는 읽기 전용 `search_documents`/`read_document` 도구를 추가해 최근 목록 밖 문서를 찾고 본문을 확인한다. 모델은 연결/선택한 서비스의 신뢰된 검색 결과나 기존 자료 ID만 읽을 수 있고 임의 URL은 호출하지 않는다. 최대4회 도구 읽기, 도구 본문 총12,000자, 모델 최대3라운드로 제한한다. 조회 실패·잘린 내용·첨부 본문은 확인했다고 하지 않는다.

외부 문서의 지시는 데이터로 취급하며 실행하지 않는다. 원본 수정/발송은 기존 검사→소유자 초안→별도 확인 경계를 유지한다. 채팅 요청만으로 원본을 쓰지 않는다.

## 시간별 브리핑과 중요한 변화

ME → 데이터·개인정보 → 브리핑·날씨 예약에서 하루 한 번/매시간을 고른다. 매시간 기본 프리셋은 **평일9–18시, 매시 정각, 하루 최대10회**다. 다른 시간대/24시간 프리셋도 선택할 수 있다. 기존 일일 예약과 날씨는 바꾸지 않는다. 실제 자동 발송은 새로 켜지 않았고 저장 전 반복 AI 사용 동의를 요구한다. 주기/자료/중요 알림 변경 때 동의를 다시 확인한다.

중요 변화 먼저 알림은 별도 스위치다. 정시 브리핑 시간 밖에도 선택한 최근 자료를 확인한다. 첫 조회는 기존 메일을 모두 긴급 알림으로 보내지 않고 기준을 만든다. 시작/알림 시각15분 이내, 오늘 기한인 미완료 내용은 서버가 판단하고 새로 바뀐 외부 자료 중 나를 지정한 즉시 요청은 AI가 판별한다. Gmail은 To/Cc와 연결된 이메일 등 확인 가능한 정보를 근거로 사용한다. 메일이나 문서 전체의 수신/지정 관계를 항상 판별할 수 있는 것은 아니다.

중요 알림은 계정/사건 키로 중복을 막고 재시작 후에도 이어간다. 한 주기 최대5건의 전달 제한 때문에 남은 사건이 사라지지 않게 이전 지문을 유지한다. 누락된 일부 조회를 삭제/변화 없음으로 간주하지 않는다. 새 연결/권한 변경이나 끄기 이후 늦은 결과는 버린다. 원본 쓰기는 하지 않는다. 읽기 실패는 상태/메시지의 한계로 표시하며 성공한 척하지 않는다.

서버가 실행 중이면 목표 확인 주기는60초다. 기존 무료 Render와 GitHub 예약 실행을 사용하므로 기동·원본 응답·예약 지연이 추가된다. 공급자 push/event 수신 경로는 아직 없으며, 이것을 보장된 실시간이라고 부르지 않는다. 기기 알림도 실제 아이폰 등록·OS 권한·Expo push 전달이 필요하다. 새 유료 자원/플랜/키를 만들거나 실제 사용자 예약을 켜지 않았다.

## 체크리스트 상태와 데이터

브리핑 텍스트 아래 같은 체크리스트를 표시한다. 체크는 완료 Todo를 한 번에 생성해log로 남기며, 오른쪽은 미완료 Todo, 왼쪽은 저장된 제안의 X 상태만 바꾼다. 이미 연결된 것은 동일 ID를 사용한다. 기존 Todo가 삭제됐으면 다른 Todo를 조용히 재생성하지 않는다. 제목이 같다는 이유로 다른 일을 변경하지 않는다. 저장 전 제목/날짜/메모 편집과44pt 대체 버튼을 유지한다.

`briefing_item_states`의 소유자+안정 키/최초 Todo INSERT는 한 트랜잭션이다. 응답 유실·동시 요청·다른 기기·다음 시간 브리핑에서 중복 Todo를 만들지 않는다. 완료 동기화는 기존 Google Tasks opt-in 범위만 사용한다. 메시지는 기존 암호화 저장, 키 매핑은 ID/상태만 보관한다. 계정 내보내기에 상태를 투영하고 계정 삭제 시 새 소유 자료도 삭제한다. 복구 bundle과 기존 DB/인증/서명은 보존한다.

## Dots와의 나머지 차이를 메우는 다음 단계

1. 사용자 계정으로 Google/Notion 문서 요청과 모델 오류/한도를 직접 재현한다. 현재는 격리 API와 모형 응답으로 검증했다.
2. Calendar 전체 선택 범위·Slack 사용자 ID/멘션·Notion 담당자 관계를 제공자별로 정확히 인덱싱한다. 현재 기본 캘린더/최근 일부라는 한계를 숨기지 않는다.
3. 서비스별 이벤트 수신·검증·갱신과 항상 실행되는 운영 경로를 연결한다. Google Calendar watch, Gmail push의 Pub/Sub 등은 실제 운영 설정과 무료/비용 조건을 검토해야 한다. Slack OAuth 설정과 해당 이벤트 권한도 필요하다. 준비 전 폴링을 실시간으로 바꾸어 부르지 않는다.
4. 장기 대화/책임·기억 관리, 사용자 관리/삭제, 출처별 지속 추적과 문서 정리 품질을 구현/검수한다. 이번 브리핑 상태 보관을 전체 개인 기억 완료로 보고하지 않는다.

[실제 검사·화면·배포 상태](assistant-briefing-qa-2026-11-15.md)를 함께 읽는다. 최신 native1.0.0(35) 이후 변경이며 새 native 빌드/설치 전 실제 기기 반영이라고 하지 않는다.
