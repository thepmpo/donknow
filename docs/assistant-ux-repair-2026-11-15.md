# 채팅·입력·일정·ME 흐름 복구

사용자가 제공한4장과 현재 ME의 실제 흐름을 점검했다. 일반형과 Duo 접힘·펼침에 같은 동작을 적용하며 일반형 하단 탭, Duo 카메라 열·반대 pane과 별도 키보드 닫기/X는 유지한다.

1. **채팅은 연결 상태 때문에 Todo 작성으로 바뀌지 않는다.** 로그인한 사용자는 상태 조회 중에도 같은 대화/입력을 유지한다. 입력·상태 도착만으로 모델을 호출하거나 Todo를 만들지 않는다. AI 미설정/실패에서도 초안을 보존하고 명시 재확인을 제공한다. 첫 화면의 오늘 내용 보기·비서·기록 찾기·대화 붙여넣기는 후속 기획 전까지 숨긴다.
2. **작성 중인 내용과 마지막 대화를 드러낸다.** 실제 keyboard screenY와 본문의 겹침만 예약한다. 키보드 위치/입력 높이·스크롤 viewport가 바뀌면 마지막 대화를 보정한다. 원래 본문 안에서 스크롤하며 별도 입력 복사 창은 만들지 않는다. 사용자가 직접 과거 대화를 읽는 스크롤은 보존한다.
3. **Todo의 배경 조회가 조작을 막지 않는다.** 이미 조회한 목록을 유지하고 배경 조회 중에도 새 저장을 허용한다. 늦은 목록/오류는 새 쓰기를 덮지 못한다. 아직 첫 목록을 읽지 못한 초기 상태, 계정 교체/인증 만료와 쓰기 직렬화는 보호한다. Todo/log의 큰 당김 표시는 직접 당긴 경우에만 나타난다.
4. **일정 입력과 원본 쓰기 권한은 구분한다.** 제목·장소·메모는 로컬 초안으로 입력할 수 있다. 원본 저장은 실제 canWrite·ETag와 기존 미리보기/확인 절차를 통과해야 한다. 열린 편집창에 새 권한·ETag를 전달하되 작성 중 초안은 덮지 않는다. 권한이 없으면 ME의 Google 연결 경로와 재확인을 안내한다. 편집 프레임을 유지하고 키보드 가림은 내부 viewport에서 빼며 메모 전체를 스크롤로 드러낸다.
5. **ME는 목록→설정 페이지→뒤로가기로 통일한다.** 기억·예약·AI 자료 관리가 별도 위로 뜨는 창을 열지 않는다. 동작 방식은 맞춤 지침/먼저 알려주기/확인 자료/자료·기능으로 나눈다. profile만 읽어 작업·파일·채널 조회에 묶이지 않으며 저장 실패 시 입력과 이전 확인 상태를 보존한다. 자동 확인과 자료 사용은 사용자가 켠 범위만 명시적으로 저장한다.

사용자의3번 오류는 JSON 응답을 읽지 못했을 때의 메시지다. 지연만으로 확정하지 않으며 당시 upstream의 실제 실패 원인은 미확인이다. 합성 서버의 HTML200 응답→정상 JSON으로 같은 종류의 실패를 재현했다. 알려진 읽기 전용 GET만1회 복구하고 POST/PATCH/DELETE·OAuth·쓰기/발송은 자동 재시도하지 않는다. 실패가 계속되면 기존 자료와 로그인 정보를 유지한 채 오류와 재시도를 표시한다.

[33장과 직접 조작 감사](assistant-ux-repair-audit-2026-11-15.md). 이전 native 실패를 고친39는 실제 Mac Swift 사전 검사·archive·Apple 업로드가 성공했다(43701986552·0f1d463). 이번 추가 UI는 그 이후다. 이번 요청에서 새 native 빌드를 자동 실행하지 않는다. 실제 UIKit 키보드/한국어 IME·VoiceOver·실계정 쓰기 검수는 남는다. 기존 사용자 자료/원본 캘린더/권한·서명·무료/수동 정책과 복구 bundle을 유지한다.
