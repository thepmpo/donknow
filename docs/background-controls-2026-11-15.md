# 겹친 팝업 뒤의 버튼 딤 — 2026-11-15

사용자 첨부2장은 Todo 편집 중 앞의 X·키보드 닫기와 뒤의 오늘·월/2주·탭이 모두 밝게 남아 겹쳐 보이는 문제다. 실제 누를 수 없는 뒤쪽 버튼을 어둡게 하라는 요청이며 X를 키보드로 바꾸거나 버튼 위치를 다시 옮기라는 뜻이 아니다.

각 앱/모달 화면에 별도 상호작용 범위를 두고 Modal이 부모 화면을 가린다. 뒤쪽의 내비게이션·오늘·보기 전환·이전 X/키보드는 기존 scrim으로 어둡게 표시하고 터치·탭/스크럽·접근성 선택을 막는다. 맨 위 화면의 X와 별도 키보드 닫기는 활성 상태로 둔다. 겹친 팝업 하나를 닫아도 그 아래 편집창이 남아 있으면 배경은 계속 막고, 마지막 팝업을 닫으면 원래 동작을 복원한다. Native fade-out 중에도 가림을 유지한다.

Duo 접힘/펼침의 좌표와 카메라 열 중심선을 유지한다. 일반 iPhone의 뒤쪽 하단 탭도 같은 처리를 사용한다. 본문은 기존 모달 배경 딤을 사용하며 이중으로 어둡게 만들지 않는다. 누를 수 있는 inline CalendarSheet의 공통 탭은 임의로 비활성화하지 않는다. 키보드 닫기와 X의 실제 기능·초안·저장/전송 경계를 유지한다.

`mobile/e2e/background-controls.mjs`로 같은 Expo Form/Modal/Navigation을 직접 실행했다. 접힘/펼침, dark/일반폰, 뒤쪽 버튼 disabled/scrim과 foreground 두 버튼, nested 모달 한 단계씩 복원, 배경 좌표 보존, 작성 메모 보존, 저장·탭·이전 동작0을 검사했다. 합성 화면8장과 verification.json을 `artifacts/background-controls-2026-11-15/current`에 보관했다. 실제 iOS native window/VoiceOver/Glass 렌더는 이 환경에서 실행하지 못했다. 사진 원본/실제 개인 데이터는 공개하지 않는다.

이번 작업 중 사용자가 즉시 수신·장기 기억·Slack 연결까지 추가 요청했다. 별도 비서 작업으로 계속 진행하며 이 딤 수정과 함께 전달한다. 아직 새 native 빌드를 시작하지 않았다.
