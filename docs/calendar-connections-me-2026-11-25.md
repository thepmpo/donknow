# 캘린더 입력 정리와 ME 연결 관리 — 2026-11-25

## 최신 사용자 결정

캘린더·서비스의 연결, 재인증, 접근 권한과 계정 관리는 **ME → 연결 서비스**에서 한다. 캘린더 안에서 OAuth나 기기 접근 승인 화면을 열지 않는다. 일정 입력에서는 이미 연결한 실제 캘린더 중 저장할 대상을 선택한다. 연결 실패 시 ME로 이동하는 버튼을 제공하고, 돌아왔을 때 날짜·제목·메모 등 기존 초안을 복원한다. Duo 고정 캘린더는 남겨 두고 다른 영역에 ME를 연다.

Google 캘린더·Google Tasks, 아이폰 캘린더·미리 알림은 필수 대상이다. Google 문서·스프레드시트·프레젠테이션·Drive, Notion, 네이버 메일·캘린더도 요구 범위다. 목록에 표시되는 제목만으로 AI가 문서를 읽었다고 처리하지 않는다. 실제 지원·실계정 확인·미구현을 아래에서 구분한다.

## 화면 변경

- 위치/영상, 시간대, 첨부 파일 추가 UI를 일정 입력에서 제거했다. 시간대는 기존 캘린더 설정값으로 계산한다. 기존 원본 장소·첨부 메타데이터를 임의 삭제하지 않는다.
- 반복/초대 기능을 쓸 수 없다는 일반 안내, 하단 원본 저장 설명, ‘세부사항 접기’ 문구를 제거했다. 메모와 URL 입력은 남긴다.
- ‘docen 알림’을 ‘알림’으로 바꿨다. 각 선택 행은 최소 48pt, 체크 표시 자리 24pt를 고정한다. 0분은 ‘시작 시간’이다. 알림 메뉴 안의 전역 예약 오류·시간대 미리보기는 제거했다. 실제 알림 예약 로직과 ME 진단은 유지한다.
- 월 보기의 가로 구분선을 날짜 셀의 위 테두리 대신 주마다 독립된 선으로 그린다. 오늘 음영의 둥근 모서리가 선을 끊지 않으며, 앞·뒤 달의 날짜 칸까지 선을 늘리지 않는다.
- 소스 목록을 읽기 전 ‘기본 캘린더/읽기 전용’을 가짜로 만들지 않는다. 확인 중·연결 확인 상태를 구분하고, 조회 실패 시 기존에 확인한 실제 소스는 유지한다.

## Google 인증 문제의 확인 범위와 복구

Render 운영 로그에서 Google 토큰 갱신 요청이 반복적으로 재승인 오류로 거절되는 것을 확인했다. 네트워크 시간 초과도 별도로 관측됐다. 로그만으로 사용자가 철회했는지, 공급자 정책/테스트 인증 만료인지 단정하지 않는다.

`server/integrations.js`는 사용자·공급자·연결 ID별로 거절된 인증 정보의 SHA-256 지문을 메모리에 보관한다. 같은 거절된 토큰을 반복 갱신하지 않으며, 새 인증 정보가 저장되면 다시 요청한다. 동시 갱신은 기존 lock으로 한 번만 처리한다. 일시적인 네트워크 오류를 영구 재인증 상태로 저장하지 않는다. 재인증 오류 최초에는 기존 AI 알림 저장 경로로 ME 안내와 원본 서비스 대안을 남긴다. 토큰 원문은 로그나 AI에 보내지 않는다.

이 변경으로 이미 무효인 Google 토큰이 유효해지는 것은 아니다. 사용자는 **ME → Google 캘린더 → 연결 권한 관리 → 연결 권한 다시 선택**에서 한 번 승인해야 한다. OAuth 복귀 시 동일한 권한 목록이어도 캘린더 목록과 일정 읽기를 갱신한다. 소스 목록 조회와 원본 쓰기의 권한은 구분한다.

## 연결별 구현과 한계

| 대상 | 코드 경로와 현재 동작 | 실제 확인이 필요한 부분 |
| --- | --- | --- |
| Google Calendar | 기존 서버 OAuth·실제 소스·원본 생성/수정/삭제·ETag 보호. ME 관리 경로로 통일 | 운영 계정 재승인 후 원본 반영 |
| Google Tasks | 기존 Todo 가져오기·완료/복원·원본 쓰기 경로 유지, ME에서 독립된 행 표시 | 실제 계정의 쓰기 권한/동기화 설정 |
| Google Docs/Sheets/Slides/Drive | 기존 agent 상세 읽기 사용. 일반 자료 읽기도 Docs/Slides 본문과 Sheets 셀 값으로 연결 | 파일 접근 권한, 문서 형식/크기/범위별 제한 |
| Notion | 기존 API의 하위 블록·페이지네이션 본문 읽기와 명시적 쓰기 | 연결에 공유한 실제 페이지·권한 |
| 네이버 메일 | ME 앱 비밀번호 입력 화면을 기존 IMAP TLS 백엔드에 연결. 기본은 읽기만 요청 | 서버 `NAVER_MAIL_ENABLED=true`, 실제 IMAP 계정 설정. 비밀번호는 채팅으로 받지 않는다 |
| 아이폰 캘린더 | 새 EventKit 어댑터로 실제 기기 캘린더/일정 읽기, 원본 생성/수정/해당 반복 건 삭제 | 새 iPhone 빌드 설치와 기기 전체 캘린더 접근 승인 |
| 아이폰 미리 알림 | 기존 모든 목록 미완료 가져오기·원본 완료/복원·동기화 경로 유지 | 실제 iPhone 기기/권한 확인 |
| 네이버 캘린더 | **아이폰에 등록된 CalDAV 캘린더**를 EventKit으로 읽고, 실제 쓰기 가능한 원본에 저장 | iPhone 계정 등록과 공급자 동기화. PC/웹의 직접 CalDAV 연결은 미구현 |

Google Sheets의 일반 자료 읽기는 첫 3개 시트의 각 `A1:Z200` 셀 값을 실제로 읽고 `partial:true`를 반환한다. 필요한 나머지는 기존 agent 범위 읽기로 이어 간다. 제목/설명만 읽고 전체 문서를 이해했다고 표시하지 않는다. 기존 파일 크기·본문 한도와 명시적 AI 자료 사용 동의를 유지한다.

네이버 공식 자료:

- [아이폰/iPad CalDAV 안내](https://help.naver.com/service/5620/contents/2426?lang=ko): `caldav.calendar.naver.com`에 등록한 기기 캘린더를 사용하는 경로다.
- [네이버 Calendar API](https://developers.naver.com/docs/login/calendar-api/calendar-api.md): 공개 문서에서 확인한 일정 생성 API를 전체 조회·수정·삭제 API가 있는 근거로 확대하지 않는다.

## 아이폰 캘린더 구현 상세

`apple-calendar-device.ts`는 설치된 Expo Calendar 58의 새 API를 사용한다. 런타임에서 예외가 나는 deprecated `get*Async` 메서드를 새로 사용하지 않는다. `getCalendarPermissions(false)`와 `requestCalendarPermissions(false)`로 전체 접근을 확인하고, 실제 승인 요청은 ME에서만 한다. 웹에서는 기기 연결을 제공하지 않는다.

`@apple/<encoded calendar ID>`를 Google ID와 분리해 Apple ID를 Google API로 전송하지 않는다. 계정 소유자별 선택 목록과 캐시를 사용하고, 읽기는 기기 앱 활성화·선택 날짜 범위·30초 갱신 기준이다. 네이버 CalDAV인지 계정 이름으로 추측해 권한을 만들어 내지 않는다. 기기가 반환한 `allowsModifications`를 사용한다.

원본 저장 전 권한·쓰기 가능한 소스·계정 유지·현재 원본 버전을 확인한다. 원본 버전에는 수정시각과 실제 내용/날짜/반복/알림을 반영한다. 변경된 필드만 저장해 기존 장소·반복·초대·알림을 보존한다. 부분 표시된 긴 메모를 짧은 텍스트로 덮어쓰지 않는다. 반복 일정 편집/삭제는 선택한 발생 건으로 제한한다. native 초대와 캘린더 간 이동은 원본 앱에서 진행하며 지원한 것처럼 표시하지 않는다.

native 생성/수정/삭제를 서버 Google action으로 보내지 않는다. 응답이 불명확한 쓰기는 자동 재실행하지 않는다. 확인 중에는 중복 버튼 동작을 차단하고 원본 앱/일정 새로 확인을 안내한다. mock 테스트는 실제 EventKit의 계정 동기화 성공을 증명하지 않는다.

## 기기 자료를 AI에 전달하는 경계

서버 AI가 아이폰 EventKit을 항상 직접 읽을 수 있는 구조는 아니다. ME에서 사용자가 선택한 캘린더와 날짜 범위의 **실제 제목·메모·시작/종료·장소·URL**을 JSON 파일로 AI 입력창에 전달할 수 있게 했다. 현재 열린 앱의 기존 파일 업로드와 자료 사용 동의를 사용하며 자동 전송은 하지 않는다(`autoSend:false`). 사용자가 채팅에서 확인하고 전송한다. 선택하지 않은 캘린더의 본문은 제외하며 파일은 4MiB를 넘으면 범위를 줄이도록 한다. 비밀번호/토큰은 자료에 넣지 않는다.

## 검증과 게시 구분

자동 검증 명령:

```sh
npm run check
npm test
npm --prefix mobile run typecheck
npm --prefix mobile run check:native
EXPO_NO_TELEMETRY=1 CI=1 npm --prefix mobile run export:ios
node mobile/e2e/calendar-create.mjs
node mobile/e2e/apple-calendar-workspace.mjs
```

실제 React Native 웹 컴포넌트 + Chromium + 합성 API/기기 어댑터로 ME 이동/초안 복원, 재인증, 원본 한 번 쓰기, 알림 정렬, 구분선, native 생성/부분수정/삭제, 실제 본문 파일 전달과 Google 쓰기 0회를 확인한다. 단위 검증은 권한 부족·계정 변경·원본 충돌·불명확한 결과에서 재시도하지 않음을 포함한다. 캡처는 `artifacts/calendar-compose-cleanup/`, `artifacts/core-calendar-connections/`의 합성 자료다.

검증 결과와 실제 배포 상태는 `docs/change-log.md` 최신 항목에 기록한다. iOS JS export, GitHub push, Render 서버 배포, 서명 IPA/TestFlight 제출, 실제 사용자 계정/기기 검수는 서로 다른 상태다. GitHub 수동 TestFlight dispatch는 이전 연결 권한으로 `Forbidden`이어서 새 제출 성공으로 보고하지 않는다. 소개 사이트 공개 범위와 PG/요금제/서명 ID는 바꾸지 않는다.
