## 현재 덕 캡처 기반 문제

같은 작업에서 실제 Expo 웹을 새로 실행해 `artifacts/calendar-navigation-2026-11-14/before/`에 저장/열어 확인했다. 원본은390×844 CSS/DPR2·2026-11-14 예시 계정이며 실제 사용자 기기 캡처가 아니다.

1. 년월 시트는 이전/다음·Today·보기·검색·추가·연결/새로고침·년월값·적용·취소·닫기를 함께 담고 있다. 날짜 선택과 작업 메뉴가 혼합됨.
2. 웹은 년/월 select2개, native 분기는 연도 이동/12개월 선택과 추가 버튼들이다. 웹 select 모양을 native iPhone의 실제 외형으로 제시하지 않는다.
3. 일반 iPhone의Today는 년월 시트 안에 숨겨져 있다. 탭 재선택은 빠른 경로가 될 수 있지만 눈에 보이는 경로도 유지해야 함.
4. 길게 누르기를 추가할 때 기존 Glass 누름/끌기/취소 제스처와 탭 선택이 중복 실행되면 안 된다. 길게 누른 뒤 손을 떼면서 Today가 다시 실행되거나, 다른 탭을 끌어서 선택한 것을 재선택으로 해석하면 안 됨.

## 공식 자료 비교

- [Apple Context menus](https://developer.apple.com/design/human-interface-guidelines/context-menus): 소수의 관련 동작·기본 UI에서도 접근·일관성. 공식 Markdown도 직접 읽었다.
- [Apple Pickers](https://developer.apple.com/design/human-interface-guidelines/pickers): 맥락 가까이·좁은 공간은compact·별도 확인 대신 바깥 탭으로 닫는 선택 방식. **날짜 입력 picker와 Calendar의 연간 탐색은 구분**한다.
- [Apple Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars): 탭은 최상위 영역 전환과 상태 보존이 기본. 요청한 재탭/길게 누르기는 덕의 추가 단축 조작이며 Apple이 동일 동작을 요구한다고 하지 않는다.
- [Fantastical Getting started](https://flexibits.com/fantastical-ios/help/getting-started), Viewing different dates 절: 년월 헤더 탭→오늘, 길게 누르기→특정 날짜 이동. 공식 문서를 읽은 비교이며 실제 Fantastical iPhone 앱 조작 검수는 아님.

추천: 사용자 영상의 연간 탐색을 날짜 이동에 사용하고, 기타 명령은 하나의더보기로 분리. 일반 iPhone의 상단2주 버튼과 Duo의Today/2주 독립 버튼은 유지하는 방향으로 질문했다. 계정/원본 쓰기·캐시·화면 채우기/스크롤 계약은 변경하지 않는다.

## 기기별 확인 질문 — 아직 결정 전

1. 일반 iPhone: 선택 중 캘린더 재탭→Today, 길게 누르기→2주, 다른 탭에서 돌아오면 마지막 날짜 유지. 대안은 들어올 때마다Today.

3. 년월: 두 기기 모두 영상처럼 연간→월 직접 이동/기타더보기로 정리할지, 일반폰은작은선택창/Duo만연간으로 할지.
