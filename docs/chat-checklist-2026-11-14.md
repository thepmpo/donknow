# 채팅 체크리스트 — 완료·제외·Todo 저장

상태: **‘구현하자’ 승인 후 코드/합성 API·기기별 웹 검수 완료, 새 TestFlight 설치·실기기 검수 대기**. 일반 iPhone과 Duo 접힘·펼침에 같은 동작을 적용한다. 기존의 ‘채팅 안에서만 완료 표시’는 이 계약으로 대체한다.

## 사용자가 하는 일

한 AI 답변의 구조화된 할 일 후보를 항목별 카드로 보여준다. 답변을 받거나 읽었다고 자동 저장하지 않는다. 각 답변은 기존 서버 형식의 최대8개 제안을 사용하며 일반 문장의 모든 글머리표를 임의로 Todo로 해석하지 않는다.

| 조작 | 채팅 표시 | 실제 저장 |
|---|---|---|
| 빈 체크박스 누르기 | 체크와 취소선, 완료 후 log 보기 | 새 후보는 처음부터 완료된 기록으로 저장. 이미 추가한 후보는 같은 Todo ID를 완료 처리 |
| 왼쪽 스와이프 | 체크박스 안 X와 ‘채팅에서 제외됨’, 되돌리기 | 없음. 연결된 기존 Todo/log도 삭제하거나 상태 변경하지 않음 |
| 오른쪽 스와이프 | ‘Todo에 추가됨 · 보기’ | 미완료 Todo에 추가. 이미 연결된 항목은 같은 ID를 재사용. 완료 상태였다면 기존 항목을 미완료로 복원 |

체크 해제는 연결된 같은 항목을 미완료로 복원한다. X의 되돌리기는 후보 표시만 복원한다. ‘제외’와 ‘Todo에 추가’ 버튼도44pt 이상으로 남겨 스와이프를 쓰기 어려운 경우 같은 조작을 제공한다. 제목/날짜/메모는 저장 전에 편집하며 불확실한 저장 요청의 내용은 잠근다. 저장 뒤에는 실제 Todo 제목과 상태를 표시한다.

Todo↔log 사이에서 이미 존재하는 항목이 이동할 때의 **3초 되돌리기와350ms fade**는 기존 `useTodos`를 그대로 사용한다. 채팅에서 처음 완료로 저장하는 기록은 중간 미완료 Todo를 만들지 않고 log에 바로 저장한다. 별도의 가짜3초 중간 항목을 양쪽에 동시에 넣지 않는다.

## 기기·제스처·읽기 흐름

- 일반 iPhone: 채팅 본문 안 후보 카드에서만 좌우 조작. 기존 하단 탭·키보드 완료 바·입력창/초안은 유지한다.
- Duo 접힘: 같은 카드 조작, 카메라 열/세로5탭·오늘·2주·바깥 스크롤바 위치를 유지한다.
- Duo 펼친 가로: 오른쪽 선택 본문 안에서만 같은 조작. 왼쪽 고정 Calendar와 구분선은 바꾸지 않는다. 펼친 세로는 기존 전체 선택 화면에 같은 카드 조작이다.
- 세로 스크롤은 그대로 둔다. 수평12pt·수평/수직1.4배를 넘은 때만 잡고 전체 수평64pt 이상에서 확정한다. responder 획득 전에 움직인 거리도 포함한다. 잡은 수평 조작의 중간 탈취를 막고 OS 취소는 작업 없이 복귀한다. 이동은±88pt, 복귀180ms이며 동작 줄이기에서는 즉시 복귀한다. 이 값은 덕의 구현값이며 Apple 규격이 아니다.
- 저장 결과/오류는 해당 카드 위치로 보이게 한다. 긴 답변과 편집 영역 접힘 이후에도 입력창 뒤로 결과가 가려지지 않도록 부모 답변+카드 좌표로 계산한다. 계정 변경 뒤 늦은 결과가 다른 계정을 스크롤하지 않는다.

## 저장·실패·중복 계약

`assistant-checklist.ts`가 답변 ID+제안 위치별 `ChecklistEntry`의 서버 action ID/반환 Todo ID를 유지한다. `useAssistant`의 작업 잠금을 공유하고 `AssistantChecklist.tsx`는 UI/제스처를 맡는다. 비교 기준은 서버 ID이며 같은 제목인 다른 할 일을 잘못 완료하지 않는다. 서로 다른 답변의 같은 문장을 하나로 합친다고 약속하지 않는다.

첫 저장은 `/api/capabilities`의 `assistantChecklist:1`을 확인한 후, 기존 owner-scoped action의 prepare→명시 확인을 **체크/스와이프/버튼이라는 사용자 조작 안에서** 진행한다. 추가 확인창은 요구하지 않는다. 일반 외부 서비스 실행의 별도 미리보기/확인은 유지한다. 새 `todo.create.args.done`은 boolean만 허용한다. 기존 모델/수동 생성 카탈로그에는 이 내부 옵션을 추가 노출하지 않아 다른 생성 화면은 유지한다. `store.create`의 별도 완료 옵션으로 단일 INSERT에 done/completedAt을 함께 기록하며 일반 Todo 생성은 기존처럼 미완료다. 새 DB 스키마/로그인·암호화 키 변경은 없다.

확인 응답이 유실되면 원래 action ID를 읽어 성공을 복구한다. running/unknown 결과에는 새 create/confirm을 보내지 않는다. 확실히 pending인 원래 작업만 사용자의 다음 조작에서 재확인한다. 원래 의도와 다른 동작을 골랐는데 앞 요청을 확정한 경우 실제 결과를 표시하고 다음 선택을 요청한다. 저장 실패는 체크 성공으로 표시하지 않는다. 반환 ID의 항목이 삭제되어도 다른 동일 제목을 변경하거나 새 항목을 몰래 만들지 않는다.

계정/서버 변경 시 후보 상태를 분리하고 요청 전후 세대를 확인한다. 실제 저장 항목은 기존 서버 Todo/log에 남는다. **전체 채팅과 X 표시를 앱 완전 재시작 후 복원하는 기능은 이번 범위가 아니다.** 기존 외부 자료의 원본 ID/권한·Tasks 동기화 opt-in을 확대하지 않는다. 모델이나 운영 Google 쓰기를 대신 실행하지 않았다.
