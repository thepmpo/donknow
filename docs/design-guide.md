# duckduck 디자인 적용 기준

## 최신 구현 계약 — 2026-11-13 · 이전 규칙보다 우선

[전체 현재 기준서](continuation-guide.md)와 [Liquid Glass 구현 계약](liquid-glass-navigation.md)에 제품의 확정 결정·원본 파일·정확한 수치·상태 전이·접근성·테스트·실기기 미확인을 모았습니다. 다른 채팅은 이 두 문서부터 읽고, 다른 서비스는 [공통 원칙 v1.1](reusable-product-design-principles.md)의 공통 부분을 재사용합니다. 아래 날짜별 절은 변경 이력이며 오래된 상태를 다시 적용하지 않습니다.

- 일반 iPhone: 화면 끝까지 채운 평평한 바에서 **떠 있는 하단 capsule**로 변경. 좌우12pt, bottom=max(safeInset,8pt), radius32, 내부4pt. 기존 ‘capsule/외부 여백 금지’는 이번 사용자 지시로 대체합니다. 흰 본문은 유지하며 가짜 무늬나 배경색을 추가하지 않습니다.
- 바는 regular Glass. 선택 표시는 평소 중립 강조, 누르면1.08배/100ms 확대·Glass, 끌면 실제 포인터를 따라 이동, 손을 떼면250ms 중앙 정렬·180ms 축소/재질 해제. 밖에서 떼거나 취소하면 원래 탭을 유지합니다. 이 수치는 덕의 값이며 Apple 공식 고정 수치가 아닙니다.
- 기존 5개 탭/순서는 유지. 짧은 표시명 캘린더/할 일/덕/log/내정보, 접근성 이름은 보존. 큰 글자는 필요하면 두 줄로 표시하고 최소44pt 조작을 유지합니다.
- native iOS26+ 가용성 검사, 구버전/웹 블러 대체, 투명도 줄이기·고대비 불투명, 동작 줄이기 확대/지연 없음. 장식 Glass의 isInteractive만으로 네이티브 탭 반응이 완성됐다고 설명하지 않습니다. RN 제스처를 직접 연결합니다.
- Duo의 물리 카메라 열·64×272/52/28·분할선·좌측 Calendar 고정/오른쪽 선택·회전 상태는 유지합니다. 브리핑/날씨의 문서 대기는 해제됐고 예약 덕 채팅 계약을 따릅니다.
- 실제21번은1f7dc5d의 무료 Mac 빌드·Apple 업로드 성공, 사용자가 Glass 외형 확인. **이번 터치/하단 수정은21 이후**이며 새 설치 전에는 폰이 바뀌지 않습니다. App Store와 동일한 물리 효과/전체 기기 검수를 완료했다고 하지 않습니다.


## 2026-11-13 — Duo 오른쪽 세로 탭과 예약 메시지

Duo는 본문 안쪽 오른쪽이 아니라 **물리 카메라가 있는 맨 오른쪽 열**에 내비게이션을 둔다. 접힘·펼침 모두 그 열 아래에 세로5개 탭, 카메라/상태 표시 아래에는 실제 복귀·닫기 경로에서만 원형 ‹를 표시한다. 상·하 안전 여백8pt,64×272pt 묶음·52pt 조작·28pt 아이콘을 유지한다. 펼친 가로 화면은 왼쪽 캘린더 고정·오른쪽 최초 Todo이며 탭 선택은 오른쪽만 바꾼다. 펼친 세로 화면과 접힌 화면은 선택 중인 화면 하나를 본문 전체에 표시한다. 회전·접힘 시 현재 탭·입력·편집·캘린더 월·스크롤을 보존한다. 일반 iPhone은 기존 하단 탭이다.

전체 네이티브 좌표에서 조작부와 본문을 분리한다. 본문에64pt 여백을 넣어 카메라 왼쪽으로 밀던 해석은 폐기한다. 분할은 Apple 힌지 상태 fullyOpen과 가로 방향에서만 켠다. 치수는 UI 토큰이며 기기 탐지 조건이 아니다. [승인 그림·새 미리보기·실기기 검수](iphone-duo-support.md).

사용자는 내비게이션 확대와 Apple Liquid Glass·선택 이동을 승인했다. Duo는 아이콘28pt·터치52pt·세로 바64×272pt로 확대한다. native Glass는 지원하는 iOS에서만 사용하고 웹/이전OS는 블러 대체, 투명도 줄이기/고대비는 불투명 재질이다. 선택 강조판은 실제 탭 좌표로250ms 이동하고1.06배 반응하며 동작 줄이기에서는 즉시 선택한다. 빠른 탭 변경은 이전 이동을 취소한다. 일반 iPhone은 기존 하단 위치를 유지한다. 시트/본문/전체 앱 디자인을 임의로 Glass로 바꾸지 않는다. [새 미리보기·native/웹 구분·검수](iphone-duo-support.md).

사용자가 좌우 구분선 시안을 승인했다. 펼친 가로 Duo의 실제 pane gutter 중앙에 기존 line 색 #E5E8EB·StyleSheet.hairlineWidth의 장식 선을 두고 양끝16pt를 띄운다. 스크롤/탭과 독립적으로 고정하고 터치·접근성 항목을 만들지 않는다. 세로/접힘/일반 기기/분할 비활성에는 숨기며 활성 힌지/가림과 충돌하면 중복해 그리지 않는다. [승인 원본·실제 구현·검수](duo-pane-divider-proposal-2026-11-13.md).

선택 Glass 정정: 이전 움직이는 파란 선택 원은 일반 색상 View였고 바 배경만 native Glass였다. 선택 표시 자체에도 지원 iOS의 GlassView regular/isInteractive를 사용하고 파란 채움을 제거한다. 글라스 부모 opacity를 낮추거나 가장자리를 잘라 깊이를 없애지 않는다. 아이콘의 선택 파란색은 유지하며 웹/이전OS는 중립 블러 대체, 투명도 줄이기/고대비는 불투명 대비 표시다. 실제 폰 재질은 수정 후 새 설치에서 검수한다. [확정 원인·빌드20·수정·검증 한계](navigation-glass-correction-2026-11-13.md).

브리핑·날씨는 별도 화면이 기본이 아니라 설정한 시간에 덕 채팅으로 오는 메시지다. 예약은 기본 꺼짐이며 사용자가 시간·시간대·도시·자료를 정한다. 반복 AI 전송은 별도 동의, 외부 쓰기는 자동 실행하지 않는다. 작은 화면의 예약 저장은 스크롤과 분리해 고정한다. 기존 직접 조회는 오늘 내용 보기라는 보조 도구로 남긴다. [예약 동작·검증](scheduled-messages-2026-11-13.md).

## 덕의 일상 대화 — 2026-11-12

인사·감사·잡담에는 짧고 자연스러운 존댓말로 답한다. 인사만 했는데 할 일 정보가 부족하다고 하거나 부분 조회·완료 Todo 처리 규칙을 길게 설명하지 않는다. 실제 업무 요청에는 필요한 질문과 근거를 제시하고, 확인한 범위를 넘겨 말하지 않는다. 할 일 생성과 외부 실행은 기존 확인 절차를 따른다. [실제 사용자 응답과 보완](assistant-chat-feedback-2026-11-12.md).

사용자 후속 지시로 [15단계 감사](ux-ui-audit-2026-11-12.md)의10개 항목과 편집 저장 버튼 가림을 수정했다. [수정 전후·19개 화면·검증](ux-ui-fixes-2026-11-12.md)을 현재 구현 기준으로 삼는다. 도구/자료를 접어 대화를 넓히고, 후보의 제목·날짜·확인을 메모보다 먼저 둔다. 완료는 접어서 보되 원문/실행 기록을 보존한다. 붙여넣기는 채팅으로 가져온 다음 동의하고 보낸다. 권한을 먼저 고르고 아래 연결 버튼을 누르며 연결 사실과 쓰기 승인 범위를 구분한다.

권한 행·서비스 탭·월/주·이름 편집·도구·날짜 해제는 최소44pt를 지킨다. 흰 글자의 기본 버튼 배경은 기존blue700(#1b64da)을 action 용도로 사용하며 대비는 약5.41:1이다. blue500 브랜드/아이콘, 서체·모서리·5개 탭은 유지한다. 웹 날짜 선택기는 브라우저 언어를 따르고, 확인/기기 표시는 한국어 날짜, 저장은ISO다. 할 일 시트의 저장은 본문 스크롤과 분리한다. 캘린더 선택일/내 계정 바로가기를 제공하고 작은 화면 탭은 단어 단위로 줄바꿈한다. 이는 승인된 톤·IA의 세부 조작 개선이며 전체 디자인 교체가 아니다.

## 2026-11-12 — 덕 채팅의 새 결과 표시

새 답변·후보·확인 초안·실행 결과는 해당 항목의 시작 위치를 보여준다. 오래된 기록이 있다는 이유로 기록 맨 끝으로 이동하지 않는다. 자료 선택을 열면 선택 제목이 보이고, 이미 실행 초안으로 준비된 후보의 날짜는 읽기 전용으로 표시한다. 기존 색상·크기·간격·모서리·동의 후 확인 실행 원칙은 그대로다. [Product Design 검토와 전후 화면](product-design-chat-audit-2026-11-12.md).

전송 처리 상태와 오류는 입력창 바로 위에서 확인할 수 있게 한다. 실패해도 입력과 동의를 보존하고 사용자가 직접 다시 보낸다. [전송 무반응 진단과 수정](assistant-chat-feedback-2026-11-12.md).

## 덕 채팅·iPhone Duo 적용 승인 — 2026-11-12

사용자는 사무실 개발을 보류하고 덕의 남은 기능과 iPhone Duo 대응을 진행하도록 승인했다. 이전의 “Duo 진행 전 구현 금지”는 해제됐다. 기존 톤·색상·글자·5개 탭은 유지하며, 덕 채팅의 제안→확인→실행 흐름과 Apple 공식 API에 따른 Duo 우측 내비게이션을 적용한다. 일반 iPhone은 하단 내비게이션을 유지하고, Duo의 접힘·펼침에서는 탭·입력·편집·스크롤 상태와 힌지·안전 영역을 보존한다. 모델명·화면 폭만으로 기기를 판별하지 않는다.

공식 개발 문서 확인, 코드 구현, 자동 검사, iOS 네이티브 빌드, 실기기 검증은 각각 구분한다. 브리핑·날씨는 후속 간략 문서 전까지 현재 코드를 유지한다. Figma의 69개 화면 재확인 및 호출 한도는 [최신 대조 기록](figma-baseline-review-2026-11-12.md)을 따른다.

## 공식 승인 — 2026-11-10 · v1.0

승인 근거: 사용자 요청 “추천안으로 공식 확정하고 디자인 가이드와 인수인계 문서에 반영해줘”. 바로 앞 대화의 최신 추천안 **A + ② + 가**를 확정한다. 초기 분석 초안의 A + ① + 가 추천보다 이번 승인이 우선한다.

- **톤:** 차분하고 친근한 비서. 짧고 담백한 존댓말로 목적·현재 상태·다음 행동을 전달한다.
- **역할 표시:** 기본 대화 상대는 덕 하나다. 검토·설명에 필요할 때만 담당 역할을 보조 표시한다. 직원별 화면·다수 캐릭터·조직 관리를 기본 경험으로 만들지 않는다.
- **오리:** 기존 오리를 유지하며 인사·완료 같은 의미 있는 순간에 가볍게 표현한다. 상시 움직임·게임형 사무실·새 캐릭터 자산은 이번 승인 범위가 아니다.
- **실행 원칙:** AI는 근거와 후보를 제안하고, 사용자가 내용을 확인한 뒤 실행한다. 제안·확인 대기·실제 성공·실패·결과 불확실을 구분한다.
- **재사용:** RP-01~RP-12를 공식 공통 원칙 v1.0으로 확정한다. 다른 프로젝트는 브랜드·색·토큰·IA를 별도 정의하며 duckduck 고유 값을 그대로 강제하지 않는다.

당시 승인은 디자인 방향·공통 원칙과 문서 반영에 한정했다. 앱 일괄 변경·Figma 교정 완료·새 수치/시안 승인·AI 직원 도구 도입을 뜻하지 않는다. 현재 코드 토큰은 유지한다. 이후 덕 채팅·Duo 적용 범위는 위 2026-11-12 지시가 우선하고, 브리핑·날씨는 후속 간략 문서 대기를 유지한다.

공식 원칙: [재사용 원칙 v1.0](reusable-product-design-principles.md) · [쉬운 확정 요약](ai-office-tone-summary.md) · [분석과 근거](ai-office-ux-analysis.md). 아래 기존 수치·동작 계약은 별도 변경 없이 보존한다.


## 목록 밀도와 화면 참고 기준 — 2026-11-03

현재 기준은 캘린더 구성은 Fantastical, Todo 목록 밀도·조작은 Things, 공통 시각 토큰/버튼/접근성은 토스 가이드를 함께 참고하는 것이다. Todo를 우선 압축했다. 기본 행 약 60pt, 16/24 제목, 날짜/출처 단일 보조 줄, 작은 상단·추가 버튼을 사용한다. 한 화면의 항목 수를 늘리되 터치 영역 44pt를 지키고 글자 확대 시 행을 강제로 고정하지 않는다. 공개 자료/설명에 대한 참고이며 두 앱의 비공개 규격이나 현재 스크린샷을 직접 읽었다고 하지 않는다.

## 디자인 1차 적용 — 2026-11-02

사용자의 적용 요청으로 `mobile/src/theme.ts`의 공통 토큰과 네이티브 UI에 TDS 참고 규칙을 적용했다. 색상·기본 글자 크기/행간은 확인된 foundation을 사용하며, 버튼 높이·모서리·여백은 덕의 선택값이다.

- 흰 화면·진한 제목·읽기 쉬운 보조 설명, 공통 파란 주요 버튼과 옅은 보조 버튼, 로딩 표시/중복 실행 방지.
- Todo의 간결한 행·체크·예정일과 추가 버튼, 완료 후 4초 되돌리기 유지.
- 전체 42칸 달력·선택일·Google 일정·아젠다, 오리 중심의 덕 첫 화면과 초안 카드, log·내정보의 동일한 글자/표면/간격.
- 로그인 입력 라벨, 편집/붙여넣기 시트, 연결/검색/계정 안내의 작은 글자 보완. 네이티브 글자 확대는 끄지 않는다.
- 웹 체험 모드와 격리 API 화면 캡처는 `artifacts/mobile-*.png`에 갱신했다. `fixture` 이미지는 외부 서비스 테스트 응답이며 실제 사용자 데이터 캡처가 아니다.
- TypeScript, iOS JS 번들, 웹 기능 회귀 및 320/390/430 너비·글자 160% 확대 시뮬레이션을 검증한다. 이는 실제 iPhone 접근성·알림·키보드·서명 빌드 검증과 다르다.

웹은 최신 커밋을 Render에 배포해야 보이고, 기존 TestFlight 바이너리는 변경되지 않는다. iPhone에는 새 EAS 빌드와 업로드가 필요하다.

## 덕에 적용할 원칙

- 큰 제목과 충분한 여백으로 화면의 핵심을 먼저 보여준다. 안내는 행동에 필요한 만큼만 짧게 쓴다.
- 흰색·옅은 회색 표면, 진한 본문, 파란 주요 행동으로 시선을 정리한다. 모든 요소를 파란색이나 카드로 만들지 않는다.
- Todo는 체크·제목을 중심으로 유지한다. 날짜·출처는 보조 정보이며 카드와 배지를 늘리지 않는다.
- 화면마다 주요 행동을 명확히 한다. 돌아가기·취소·상세보기는 보조 행동으로 낮춘다.
- 완료·진행·오류·빈 상태를 문장과 형태로 함께 구분한다. 색만으로 의미를 전달하지 않는다.
- 아이폰 safe area·키보드·큰 글자·VoiceOver·동작 줄이기를 고려한다. 터치 영역은 최소 44pt를 확보한다.
- 스와이프 완료, 4초 되돌리기, log 복원, 권한 승인, 원본 변경 확인은 시각 수정 중에도 유지한다.

## 공통 모션 적용 — 2026-11-02

`mobile/src/motion.tsx`의 공통 전환·눌림·OS 동작 줄이기를 적용했다. 페이지는 약 180ms, 버튼 누름/복귀는 90/140ms의 짧은 반응이며 모달 전환은 플랫폼의 slide/fade를 사용한다. ## 공통 레이아웃 계약 — 2026-11-04 최신

공개 HTML은 `/design-guide`이며 `scripts/build-design-guide.py`가 `mobile/src/theme.ts`의 layout/palette에서 생성한다. ScreenHeading은 5개 탭 제목에 공통 적용한다.
