# 도슨 디자인 시스템

2026년 11월 26일 기준. 기존 화면을 고치거나 새 화면을 추가할 때 이 문서에서 공통 요소와 화면 유형을 고른다. 예전 시안과 검토 이력은 [디자인 기록](design-guide.md), 새 서비스에서 바로 실행할 코드는 [제품 스타터](../templates/product-starter/README.md)를 참고한다.

[앱 토큰 원본](../mobile/src/theme.ts)에서 역할 이름을 사용한다. CSS와 앱 화면마다 색을 새로 복제하면 테마와 대비가 서로 달라진다. [웹 작업공간 테마](../mobile/src/desktop-theme.ts)는 상단·사이드바 배경만 별도 조정한다.

- 시스템 글꼴과 글자 크기 조절을 사용한다. 제목 30/40, 헤더 26/35, 섹션 20/29, 본문 17/25.5, 목록 16/24, 보조 15/22.5, 캡션 13/19.5가 기본 크기/줄 높이다. 좁은 제품 웹의 행 밀도는 웹 작업공간 스타일을 따른다.
- 공간 토큰은 4·8·12·16·24·32, 기본 화면 좌우는 24, 헤더는 48, 일반 앱의 하단 탭은 72다. 버튼·카드·시트 반경의 기본은 16·24·28이다. 터치 조작은 최소 44pt를 확보한다.
- `MotionPressable`은 누름/놓기 90/140ms, 일반 화면 전환은 200ms, 탭 전환은 180ms, 목록 재배치는 145ms다. OS의 동작 줄이기와 투명도 줄이기, 웹 키보드 초점을 보존한다. [모션 원본](../mobile/src/motion.tsx), [내비게이션 소재](../mobile/src/NavigationGlass.tsx)
- 브랜드에는 `docen.`과 파란 점, 승인된 로고 파일을 사용한다. 소개 메인 오른쪽의 공 모션과 실제 로딩용 모션은 목적별로 적용한다. [브랜드 적용 기록](docen-brand-polish-2026-11-23.md)

## docen.ai에서 일정 만들기

일정 생성 의사가 확정되면 화면의 저장과 같은 도슨 저장 명령을 호출한다. 명령은 시작·종료·시간대, 선택한 캘린더, 재시도에 재사용할 요청 ID를 받는다. 성공 기준은 도슨 일정 ID가 반환되고 도슨 목록에 나타나는 것이다. Google 전송 결과는 그 일정에 별도로 붙이고, iPhone 전송은 해당 캘린더 접근이 허용된 기기가 수행한다. AI가 제안만 한 일정과 사용자가 생성에 동의한 일정을 구분한다. 사용자에게 외부 전송 완료를 알릴 때는 실제 원본 ID가 확인된 상태를 사용한다. 기존 AI 제안 화면을 이 저장 명령으로 연결하는 작업은 별도로 진행한다.

## 새 서비스에 적용하는 순서

1. [스타터 README](../templates/product-starter/README.md)대로 웹·iPhone 골격을 띄운다. 메뉴 이름과 아이콘, 첫 성공 흐름, 브랜드를 정한다.
2. 핵심 객체를 하나 고르고 [프로젝트 계약](templates/new-app-project-contract.md)에 입력, 저장, 편집, 취소, 완료, 실패 상태를 적는다. 예제 `CoreScreen`을 실제 객체와 저장소로 바꾼다.
3. [공통 기반 모듈](app-foundation-module-map.md)에서 필요한 계정·인증·연동·운영 모듈을 고른다. 새 제품의 도메인, Bundle ID, 저장 키 이름, 인증 앱, 운영자 역할, 정책 문구를 준비한다.
4. 필요할 때 공개 소개와 어드민을 추가한다. 소개는 핵심 가치 → 동작하는 시연 → 기능 → 문의/법적 링크 순으로 구성한다. 어드민은 인증 → 검색/목록 → 상세 → 변경 확인 → 실제 저장 상태를 한 흐름으로 검수한다.
5. [릴리스 체크리스트](app-foundation-release-checklist.md)로 검증한다. 이어받을 개발자에게 변경 위치, 확인한 표면, 남은 권한·배포와 복구 경로를 남긴다.
