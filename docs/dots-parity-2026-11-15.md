# Dots 공개 기능 전체 대응 — 덕 구현 계약

2026-11-15. 사용자의 “Dots의 전체 기능을 개발” 지시를 기준으로 한다. 브리핑·기억만 추가한 이전 범위를 대체한다. 생활·일정·업무·문서·일반 대화를 함께 돕는 개인 비서이며 모든 대화를 Todo로 만들지 않는다.

[공식 Dots](https://learn.chatgpt.com/docs/dots) · [작업·기억](https://learn.chatgpt.com/docs/dots/tasks-and-memory) · [컴퓨터·앱](https://learn.chatgpt.com/docs/dots/computers-and-apps) · [연락 방식](https://learn.chatgpt.com/docs/dots/channels) · [제어](https://learn.chatgpt.com/docs/dots/controls). 공개 문서에서 확인한 기능을 기준으로 개발했다. 비공개 내부 구현·동일 모델 품질·모든 지역의 통신 채널까지 같다고 단정하지 않는다. 이전 Help Center URL은 홈페이지로 이동하므로 원문 근거로 사용하지 않는다.

## 사용자 흐름

1. ME→연결된 서비스 안쪽에서 원하는 Google 계정·Notion·Slack·Naver의 필요한 읽기/쓰기 범위를 연결한다. 연결 목록은 ME 첫 화면에 계속 펼치지 않는다.
2. 덕 채팅의 자료 설정에서 사용할 원본을 고른다. 파일/사진 아이콘은 선택 자료를 업로드한다. 선택한 자료와 Todo의 분석 동의를 확인한 뒤 보낸다. 보낸 글은 즉시 입력창에서 지우며 전송 중 새로 작성한 글은 보존한다.
3. “자료를 확인해 보고서로 만들어줘”처럼 긴 일은 별도 작업에 맡기고 대화를 계속한다. 작은 작업 행을 누르면 진행·입력 질문·실행 확인·파일을 본다. 작업 안에서 지시를 더하거나 정지/재개한다.
4. 작업 보기의 단일 메뉴에서 작업/맡긴 일/파일/컴퓨터/연락/설정을 고른다. 전체 기능을 채팅 하단에 버튼으로 나열하지 않는다.
5. 체크리스트는 체크→완료/log, 왼쪽→X 표시만, 오른쪽→Todo 저장이다. 기존 Todo↔log의3초 유예/되돌리기와 안정 ID 중복 방지는 유지한다.
6. “매주 월요일…”, “이 요청의 답이 오면…” 같은 지속 업무는 확인한 원본·범위와 함께 책임으로 저장한다. 내용·다음 확인·진행은 작업에서 검토하고 원치 않으면 정지/삭제한다.
7. 컴퓨터가 필요한 일은 본인의 연결기와 작업을 묶는다. 화면을 보며 직접 제어→비공개 로그인→덕에게 돌려주기로 이어간다. 비밀번호/인증번호를 채팅이나 모델에게 묻지 않는다.

일반 iPhone과 Duo 접힘·펼침에 같은 흐름을 제공한다. 일반폰 하단 탭과 Duo 카메라 열·선택하지 않은 pane은 유지한다. 키보드는 기존 X 위의 별도 Duo 버튼/일반폰 키보드 위 완료, 고정 편집창 내부 scroll reveal, 누를 수 없는 배경 dim을 유지한다.

## 실행·권한·완료 계약

- 작업/단계/파일/소유자 응답은 암호화 저장한다. 모델 도구 요청은 실행 전에 checkpoint하며 단계별 안정 ID를 사용한다. 중단된 외부 쓰기는 성공/실패를 추측하거나 무조건 재실행하지 않고 결과 확인을 요구한다.
- 완료에는 실제 읽은 근거·결과 파일·실행 증거를 연결한다. 검색에서 이름만 찾은 자료는 읽었다고 승격하지 않는다. 파일/코드/컴퓨터가 요구된 일은 해당 실제 증거 없이 완료할 수 없다. 긴 자료의 다음 커서·부분 상태를 모델에 전달한다.
- 원본 쓰기는 기존 prepare→미리보기→확인 경로다. 사용자가 작업·정확한 대상·만료를 정한 권한 규칙만 자동 실행한다. ask/handoff가 allow보다 우선하며 새 연결 계정은 이전 권한을 이어받지 않는다. 개인 문맥의 외부 공유는 별도 허용이 필요하다.
- 컴퓨터의 자동 허용도 규칙 ID/개정/만료·동의·기억 상태를 poll/heartbeat 때 재확인한다. 사용자 직접 입력은 모델 단계에 넣지 않으며 처리·만료·연결 해제 때 폐기한다.
- 이벤트 연구는 원본 읽기 전용이다. 모델이 먼저 외부 글을 쓰거나 컴퓨터를 조작하지 않는다. 필요한 변화가 없으면 매번 push하지 않는다.
- visible 대화는 채널별로 분리하고 허용된 장기 기억만 이어 쓴다. 다른 사용자의 채널 요청을 주인의 요청으로 실행하지 않는다. 그룹 멘션의 개인 자료 답변은 주인의 개인 대화로 보낸다.
- 전체 기억 삭제는 검색 색인·진행 문맥·임시 채널/통화/응답을 무효화한다. 사용자 Todo/log와 저장 파일은 보존한다. 작업 삭제는 그 작업과 파일을 삭제하며 독립 자식 작업은 따로 관리한다.
- 복원은 데이터 복원이다. 작업은 paused, 책임은 off, 수신 큐/채널 코드는 삭제, 채널은 disabled, 컴퓨터는 revoked, 통화는 closed다. 이름만 수정해도 자동 활동이 재개되지 않는다. 사용자가 명시적으로 재개/재연결해야 한다.

## 구현 위치와 제한

`server/agent-{store,engine,tools,chat-tools,model,policy,events,sync,memory,files,file-queue,file-worker,computer,computer-routes,channels,media,voice,routes,schedules}.js`, `integration-agent-tools.js`, `office-document.js`가 기존 인증·원본 동작 위에 추가된다. 새 DB table은 additive이며 기존 키·계정·자료를 교체하지 않는다.

`mobile/src/screens/AgentWorkspace.tsx`, `AgentCall.tsx`, `AssistantChat.tsx`, `useAssistant.ts`, `agent.ts`, `assistant-entry.ts`, `AgentAvatar.tsx`가 제품 경로다. `companion/`은 실제 user/cloud host 실행기다. 별도 유료 worker/서버는 만들지 않았다.

작업은 계정당 진행100개, 하루 생성40개 기본(최대200), 배경 모델 turn 하루200개 기본, 한 작업200turn에서 검토 대기한다. 파일 목록은 최근200개, 작업 API는40개/최대100개 페이지다. 개인 JSON 내보내기의 작업은 최신100개와 파일 메타데이터이며 파일 원본은 파일 화면에서 내려받는다. 모든 이력을 한 번에 모델에 넣거나 무한 연산하지 않는다. HTML은 수동 문서로 작성하고 실행 분석은 격리 컴퓨터/명시 hosted-code 설정으로만 한다.

문서 생성은 별도 worker로 API를 막지 않는다. model input에는 파일/화면 ID를 보관하고 실제 전송 때만 소유자 파일을 읽는다. 최신 화면2개를 문맥에 유지하고 작업당 내부 캡처30개를 보관한다. 이 캡처도 계정 파일 한도에 포함된다. 긴 문맥은 근거·실패·제약을 보존해 요약하며 원래 도구 기록을 다시 읽을 수 있다.
