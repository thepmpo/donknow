# 가입 이메일 소유 확인 필수

사용자 정정에 따라 가입→자동 인증메일 요청→인증번호 확인→내부 진입으로 바꿨다. 이전 미인증 기본 기능 허용은 폐기했다.

- 가입/미인증 로그인: 계정을 식별하는 제한 세션만 발급한다. 메일 설정이 있으면 암호화한 outbox를 만들고 즉시 기존 worker를 깨운다. 응답에 코드를 넣지 않는다. 이 세션은 내부 이용 권한이 아니다.
- 서버: 미인증 세션은 session 조회·account 최소 메타정보·인증 send/confirm·logout만 허용한다. Todo 읽기/쓰기·일정·자료 연결·AI·내보내기·삭제 등은403 EMAIL_VERIFICATION_REQUIRED다. 과거 세션/초기 HTML/예전 앱도 서버에서 차단된다. 공개 안내·약관·댓글 조회·보안 자격증명 기반 콜백/웹훅은 회원 내부 화면과 구분한다.
- 화면: 로그인/가입 즉시 간결한 인증 화면, 현재 메일,6자리 입력,15분 안내,재전송/로그아웃만 제공한다. 새로고침/미인증 로그인도 내부 틀·탭·자료를 렌더링하지 않는다. 인증 상태 갱신 후에만 저장소를 연결하고 자료를 읽는다. 미인증 기기 알림/AI 초기화도 하지 않는다.
- 인증: 코드15분·5회 오입력 제한·재전송60초·시간당5건. 재전송은 과거 코드를 무효화한다. 실패로 코드를 폐기해도 outbox를 기준으로 재전송 제한을 지킨다. 다른 사용자 코드·만료·코드 재사용은 거절한다.
- 메일: ‘요청/전송 중/서비스가 수락한 sent/실패’를 구분한다. 공급자 테스트 수신자/발신 도메인/키/권한 등의 영구 거절은 안전한 고정 분류만 DB에 남기고 해당 코드와 대기 본문을 폐기한다. 일시적 오류는 기존 제한된 backoff를 유지한다. 수신함 도착까지 확인한 것으로 표현하지 않는다.
- 약관:2026-11-22.1 신규 발행으로 가입 인증 조건·가입 자동 메일 처리를 안내한다. 과거2026-11-22 고정 페이지와 가입 동의 기록을 변경하지 않는다. 관리자 별도 계정 정책·PG/AI 예산은 변경하지 않는다.

[브라우저 증거](../artifacts/email-verification-2026-11-22/). 테스트 메일과 공급자 응답은 합성이고 실제 회원·수신자·외부 자료에 쓰지 않았다.

## 남은 사실

Resend의 실제 발신 도메인/테스트 수신자 제한은 해소되지 않았다. 도메인 보유 여부를 사용자에게 확인 요청했다. 현재 발송 키의 도메인 조회401은 send-only 권한의 조회 거절이며 발송 자체의 정상 증거가 아니다. 새 실제 수신 테스트를 수행했다고 주장하지 않는다. 도메인 인증과 실제 수신 확인 전 일반 가입자의 정상 인증을 서비스 운영 완료로 표현하지 않는다.

기존 미인증 사용자도 인증을 끝내야 이용할 수 있다. 계정을 임의로 인증 처리하지 않는다. 인증 전용 화면은 앱 소스에도 적용했지만 이번 작업은 웹 배포이며 새 IPA/TestFlight는 빌드하지 않았다. 이전 설치 앱은 새 UI가 없으므로 웹에서 먼저 인증하거나 새 앱 빌드가 필요하다.
