## 기존 정보 구조

서버 연결 → 로그인/회원가입 → 5개 탭(캘린더, Todo 리스트, duckduck, log, 내정보).

- 캘린더: 월·주 → 날짜 선택 → 일정/할 일 아젠다. 년·월 제목 → 이동 시트. 좌우 스와이프 → 월 이동. 할 일 추가/수정은 TodoEditor.
- Google 일정 작성·수정: 덕 비서 → 자료 확인/대상 선택 → 직접 작업 작성 또는 AI 제안 → 실행 초안 확인 → 사용자 실행. 캘린더에 신규 편집기를 추가하지 않았다.
- Todo: 즉시 체크 → 3→2→1초(중간 되돌리기 가능) → 350ms 페이드·접힘 → log. log에서 미완료로 복원.
- 덕: 수동 초안/붙여넣기 → 제목·날짜·메모 확인 → Todo 추가. AI 활성화 시 서비스 선택·분석 동의 → 대화·근거·제안 → 초안 → 실행 전 확인.
- log 탭: 덕에서 완료한 Todo. 연동 실행 기록은 기존 덕 비서, 완료 동기화 전송 기록은 Google 연결 패널에 유지.
- 내정보: Google/Slack/Notion 연결·권한, 알림, 미리 알림, 데이터 내보내기, 계정. 네이버 설정은 기존 덕 비서 안에 유지.

## 표현 규칙

390×844 기준의 편집 가능한 Figma 텍스트·자동 레이아웃·컴포넌트 인스턴스다. 3페이지 제한 때문에 `00 · Screen inventory`, `01 · All wireframes`, `09 · Wireframe kit`로 분리했다. 69개 프레임은 All wireframes의 8개 구역에 있다. 화면마다 소스와 상태 설명을 붙였다. 목업 데이터는 예시이며 실제 외부 계정 성공을 의미하지 않는다.

토스 참고의 실제 소스 토큰(24pt 여백, 26/35 제목, 16/24 목록, 13/19.5 보조 글자, 공통 파란 행동)을 사용했다. Todo 밀도는 Things, 캘린더 정보 위계는 Fantastical 참고다. 저해상도 구조안이며 해당 앱의 정확한 복제나 고해상도 최종 디자인은 아니다.

원본은 iOS 시스템 글꼴이고, Figma에서 Apple SD Gothic을 찾지 못해 한국어는 사용 가능한 Noto Sans KR로 대체했다. 최종 시각 작업에서 시스템 한글 글꼴 대조가 필요하다. 키보드와 시스템 공유창은 도식이다. 정적 상태 보드이며 클릭/자동 시간 전환 프로토타입은 연결하지 않았다.

## 검증 상태와 남은 작업

- Figma 계정 연결, 파일 생성, 페이지 쓰기, 69개 프레임 생성 성공. 생성 결과에서 텍스트/프레임/인스턴스/사각형 노드 수를 확인했다. 전체 화면 래스터를 사용하지 않았다.
- 첫 캘린더 구성의 가로 자동 레이아웃 높이 오류를 수정했다. 캘린더와 Todo 목록 구역의 스크린샷을 확인했다.
- 이후 Figma Starter MCP 호출 한도에 도달해 추가 읽기·쓰기와 나머지 6개 구역의 시각 검수가 차단됐다. 유료 전환하지 않았다. 전체 검수 통과로 보고하지 않는다.
- C01 월간 예시에서 다음 달 9일에도 선택 강조/예시 이벤트가 반복된 것을 수정해야 한다. 실제 코드의 월간 로직이 아니라 와이어프레임 샘플 생성 오류다.
- C04 년·월 이동 시트는 행 높이 수정 뒤 바닥 위치를 다시 계산해야 한다. 취소 버튼이 화면 아래로 잘리는 상태다.
- `00 · Screen inventory` 페이지는 비어 있다. 위 정보 구조와 목록을 옮겨야 한다. 현재 구조 목록은 이 문서와 `artifacts/duckduck-wireframe-map.html`에서 확인 가능하다.
- 나머지 6개 구역은 최종 스크린샷, 시트/키보드/텍스트 잘림, 글꼴 대체와 source 대비 검수가 남아 있다. 모든 화면·상태를 완성 검수했다고 주장하지 않는다.

앱 런타임 코드는 변경하지 않았다. GitHub push, Render 배포, TestFlight 빌드, 원본 서비스 쓰기를 수행하지 않았다.
