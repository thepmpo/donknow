# ME — 계정·연결·알림·데이터 구현 계약

사용자의 “너가 말한 거 모두 수정해”에 따라 이전 [제품 검토](me-product-review-2026-11-14.md)의 제안을 구현했다. 일반 iPhone·Duo 모두 ME를 적용한다는 확인과 기존 기기별 범위를 따른다. 아래 내용은 제안이 아니라 현재 소스 기준이다.

## 첫 화면과 경로

첫 화면은 **내 계정 → 연결된 서비스 → 알림 → 데이터·개인정보**, 마지막에 앱 정보·도움말이다. 중복 소개·동기부여 문구·큰 계정 이동 버튼·통계 카드를 제거했다. 전체/남은/완료 수는 log의 작은 요약으로 옮겼다. 작업별 월/2주 보기와 시스템 테마는 기존 위치를 유지한다.

| 진입 | 하위 화면과 동작 |
| --- | --- |
| 프로필 한 행 | 내 계정: 표시 이름·이메일·인증·비밀번호 재설정·로그아웃·별도 계정 삭제 |
| Google/Notion/Slack 행 | 선택한 서비스 관리로 바로 이동. 다시 서비스 탭을 선택하지 않음 |
| 서비스 추가·가져오기 | 연결 가능한 서비스·아이폰 미리 알림 가져오기·준비 중인 서비스 |
| 알림 | 이 기기의 허용 상태·켜기·다시 확인·거절 시 OS 설정 이동 |
| 데이터 보관·자료 사용 | 저장 위치·파일 내보내기·개인정보 설명·고급 연결 정보 |
| 고급 연결 정보 | 명시적으로 들어왔을 때 서버 주소·설정·실제 DB/백업 상태 조회 |
| 앱 정보·도움말 | app.json의 실제 버전·사용자가 제공한 공개 문의 이메일의 메일 작성창 |

준비되지 않은 서비스에는 가짜 연결 버튼을 만들지 않는다. configured 또는 connected인 서비스만 첫 화면에 노출한다. 서버 설정이 없는 서비스는 추가 화면에 ‘준비 중’으로 표시한다. 체험 모드에서는 계정 화면의 로그인·연결 설정을 안내한다.

## 시각 규칙과 기기별 배치

`MeSettings.tsx`의 공유 MePage/MeSection/MeRow/MeDisclosure/MeCopy가 기준이다. 그룹 위 간격20pt, 제목 아래8pt, 모서리24pt. 행 최소60pt·좌우16pt·상하12pt·간격12pt, 아이콘 영역36pt/아이콘23pt, 본문17pt와 공통 semantic 색상을 사용한다. 긴 이름·설명은 최대2줄, 편집창에는 전체 값과 접근성 힌트가 있다. 고정 높이로 큰 글자를 잘라내지 않는다. 이름 수정 시 키보드를 자동으로 열지 않는다.

- 일반 iPhone: 기존 하단5탭과 본문 제목 기준선 유지. 상세는 작은44pt 뒤로가기와 전체 높이 스크롤이다.
- Duo 접힘·펼친 세로: 기존 카메라 열 탭과 원형 뒤로가기 유지, 선택한 본문에서만 이동한다.
- Duo 펼친 가로: 왼쪽 Calendar 고정, 오른쪽 ME/상세만 전환한다. 반대쪽 날짜·크기·상태는 유지한다.
- ME 하위 전환은 기존 약한 navigation fade(.98→1/220ms, scale1/translate0)를 사용한다. 강한 확대 모션을 추가하지 않는다.
- 기존 ScrollArea 규칙: 일반폰 본문 오른쪽, Duo 카메라 열 아이콘 바깥 오른쪽·1초 후 fade. 위치를 다시 바꾸지 않는다.
- 첫 화면 ScrollView는 상세 중 숨겨서 유지하며 Back 후 실제 commit 다음 프레임에 스크롤과 웹의 진입 항목 초점을 복원한다. native VoiceOver 초점은 실기기 검수 항목이다.

## 서비스의 상태·권한·가져오기

연결 상태와 실제 승인한 기능을 먼저 보여준다. 연결된 서비스는 ‘연결 권한 관리·자료 가져오기·완료 동기화(Google)·연결 문제 해결’을 접어 둔다. 새 연결은 자료와 추가 권한 선택 뒤 명시적으로 연결을 요청한다. Google 기본 연결 상태의 초기 버튼은 Back 포함5개로 검증했으며 이전 관찰은11개였다. 이는 해당 fixture의 수치이고 사용성 성과 측정이 아니다.

권한 체크와 실제 서비스 승인을 구분한다. 추가 권한의 선택은 접었다 펼쳐도 유지하지만 승인됐다고 표시하지 않는다. 완료 동기화는 해당 패널을 펼쳤을 때만 읽고, 수정 권한 요청은 실제 기존 승인 범위+tasks/tasksWrite로 만든다. 다른 화면에서 선택만 한 gmailSend 등을 몰래 포함하지 않는다. 완료 동기화 켜기는 별도 명시적 조작이다. Google scope가 제공하는 생성/수정/삭제 범위를 권한 설명에서 알린다.

GET 실패·잘못된 성공 응답·이전 응답은 연결 해제로 처리하지 않는다. 마지막 연결 상태를 보존하면서 ‘연결됨 · 상태 재확인 필요’를 표시하고 다시 확인을 제공한다. 성공하면 상태 오류를 지운다. 계정/서버/조회 세대로 늦은 응답을 격리한다. 빈 배열·잘못된 boolean/features/jobs 등의 응답도 정상처럼 렌더링하지 않는다.

자료는 명시적으로 조회하고 최대20개의 미완료 항목만 선택해 가져온다. 완료 기록은 참고용으로 유지한다. 페이지 더 보기·목록 다시 선택·중복 방지·원본 읽기와 쓰기 분리를 보존한다. 연결 해제는 별도 확인/취소 후에만 실행하며 이미 가져온 Todo를 지우지 않는다. OAuth 허용 호스트·이메일 인증·기존 서버 권한 검사는 유지한다. Naver 읽기 전용 정책은 변경하지 않는다.

## 계정·알림·자료 설명

표시 이름 키 `duckduck.mobile.name.<userId|demo>`를 유지한다. 이 기기에서만 쓰는 이름이며 계정 동기화라고 안내하지 않는다. 저장 완료 전 다른 계정으로 바뀌면 새 계정 화면을 갱신하지 않는다. 이름/계정/알림 상태는 소유자가 바뀌면 초기화하고 다시 읽는다.

알림은 실제 expo-notifications 권한에서 unknown/allowed/denied를 얻는다. 웹 스위치는 비활성으로 아이폰 앱을 안내한다. 거절은 기기 설정 열기→복귀→이 화면에서 켜기, 오류는 다시 확인이다. 권한창 대기 중 로그아웃해도 이전 계정 결과를 새 계정에 적용하지 않는다. 기존60개 알림 계획·일정 캐시·사용자별 설정을 보존한다. 실제 native 권한창·수신은 별도 검수다.

개인정보는 저장 자료·대화/임시 입력/준비한 초안/완료 실행 기록·AI 자료 동의·서비스 해제·계정 삭제의 짧은 문단으로 나눈다. 모든 초안이 종료 시 삭제된다는 과장 설명을 제거했다. 실제 동기화 시각이 없으면 만들어 표시하지 않는다. 개인 JSON 내보내기에서 연결 키/토큰을 제외하며, 비밀번호·동의가 필요한 계정 삭제 절차를 유지한다. 문의하기는 사용자가 누르면 메일 작성창만 열고 자동 발송하지 않는다.

## 수정 위치·재현·남은 확인

ProfileScreen(계층/owner/복귀), MeSettings(공통 시각), IntegrationsScreen(서비스별 점진 노출), integration-settings(응답 검증/쉬운 scope), TaskSyncPanel(잘못된 응답 복구), useReminders(권한/owner), AccountScreen/AppleRemindersScreen(공통 헤더), LogScreen(작은 통계), Page(선택적 scroll/ref)가 구현 원본이다.

[QA와 새 캡처](me-settings-qa-2026-11-14.md)를 함께 읽는다. 자동 검사·합성 웹 기하와 실제 사용자 계정/native 검수를 구분한다. **최근 확인된 native1.0.0(30) 이후 수정으로 새 빌드와 TestFlight 업데이트가 필요하다. 이 요청에서는 추가 native 빌드를 시작하지 않는다.** 무료/수동 빌드·원본 bundle·데이터/인증/서명·AI사무실/소개 사이트 보류를 보존한다.
