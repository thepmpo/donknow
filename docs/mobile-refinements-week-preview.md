# 2026-11-25 — 모바일 후속 1~6번 반영 및 1주 뷰 시안

## 요청별 상태
1. 앱 헤더의 docen. 워드마크를 확대: 기본26px(기존20px), 좁은 내부 폭240pt 미만20px(기존16px). 56pt 헤더 높이는 유지. 좁은 화면은 글자 간격/중앙 제목 폭도 함께 조정해 겹침을 줄인다. 그림 내비게이션/OS 앱아이콘/홈페이지 로고 크기 변경으로 확장하지 않는다.
2. 캘린더 일간 목록은 좌우24pt, 위16pt 여백. 날짜 스트립에만 붙어 있던 좌우 제스처를 일간 본문 표면 전체로 넓혔다. 수평20pt/수직비율1.6 조건, 55pt 이상 release로 이전/다음 하루 이동, 작은 움직임은 복귀한다. 본문 세로 스크롤과 행 편집은 보존한다. periodShift의 기존 월/연 경계 계산과 캐시/계정 보호를 사용한다. 옆 날짜를 보이는 모션도 일간 목록에 적용했다.
3. 월 선택은 두 번째 줄 왼쪽. 옆의 ellipsis 버튼은 제거. 년월 누르면 년간 보기, 길게 누르면 기존 캘린더 메뉴(설정/검색/원본 선택 등)를 연다. 힌트 및 접근성 longpress 동작도 제공한다. 기능을 무단 삭제하거나 서버권한을 바꾸지 않는다.
4. 할 일의 날짜별/출처별/추가 줄은 PagePinned 보조 헤더. Page에서 본문 ScrollView 밖으로 옮겨 당김/세로 스크롤 중 좌표가 유지된다. 편집/선택/이동 기능은 보존한다.
5. AI 화면 왼쪽 브랜드에 ai를 붙여 docen.ai로 표시하고 가운데 중복 제목은 렌더링하지 않는다. 채팅 발신자/원본 브랜드/기술 ID는 바꾸지 않는다.
6. log의 ‘완료한 기록’ 소제목만 삭제. 전체/남은/완료 수치 및 ‘docen에서 완료한 일을 모아두었어요.’를 PagePinned에 넣어 고정한다. 실제 완료 목록만 스크롤된다.
7. 기존2주뷰를1주뷰로 바꾸는 작업은 **시안 단계만 진행**. 실제 CalendarView/주기/조회범위/기기별 보기 전환/2주 UI는 아직 바꾸지 않는다. 사용자가 손그림을 참고해 먼저 시안을 보라고 명시했다.

## 1주 시안의 해석과 경계
- 월~금은 5개의 동일한 세로 열. 오른쪽 여섯 번째 열은 위 토요일/아래 일요일로 반씩 나눈다.
- 물리 카메라와 기존 내비게이션은 더 오른쪽 별도 예약 열에 둬 일정 내용과 겹치지 않게 제안했다. 카메라 위치를 소프트웨어로 옮기거나 그 위에 내용을 그리는 구현이 아니다.
- 선택일은 파란 원/옅은 배경, 토요일 파랑/일요일 빨강. 일정은 시간+짧은 제목, 할 일은 체크박스로 구분한다. 주간 이동/항목 상세 같은 문구는 제안 UI다.
- 가로에서는 상세 제목을 읽기 편하게, 세로에서는 6개 열이 좁아 짧은 요약+눌러 상세를 제안한다. 세로 화면의 좁은 열은 확정된 해법이 아니므로 시안 확인 뒤 결정해야 한다.
- design-previews/docen-one-week/index.html은 서비스와 분리된 HTML 시안이다. 합성 일정이며 실제 계정/API를 연결하지 않았다. 이전/다음 주 버튼은 시안 날짜만 바꾼다. 홈페이지 배포 경로에 복사하지 않았다.
- PNG: artifacts/mobile-refinements-week-preview/06-week-landscape-proposal.png 및 07-week-portrait-proposal.png. 사용자 스케치/개인 영상 원본은 공개 저장소에 넣지 않는다.

- CalendarScreen: 월 컨트롤 순서/메뉴 버튼 제거, 일간 본문 여백과 제스처 범위, 날짜별 agenda 인자 및 캐시 기반 인접 일자 미리보기.
- fixed-header-refresh.mjs: 이전 회귀검사를 확장했다. HEADER_CAPTURE_DIR로 이번 증거를 별도 폴더에 기록해 이전 증거를 덮지 않는다.

## 후속 확정 — 시간순과 화~수 여러 날 일정, 논 Duo 시안
사용자가 1주 레이아웃 방향을 ‘맞아’로 확인하고 시간순 정렬, 화요일부터 수요일까지 이어지는 일정 예시, 논 Duo 시안을 추가로 요청했다. 이 후속 요청도 시안을 그리는 범위다. 앱의 기존2주뷰는 아직 변경하지 않는다.

### 공통 정보 표현
- 여러 날에 걸친 일정은 날짜 제목 아래 별도 띠에서 연속 막대로 연결한다. 예시는 팀 워크숍, 2026-11-24(화)~25(수). 막대의 시작/끝은 두 날짜의 열과 일치한다. 가로에서는 제목 옆 날짜 범위, 세로에서는 짧은 제목과 아래 설명으로 범위를 확인한다. 접근성 라벨에는 전체 시작/종료 날짜를 넣었다.
- 각 날짜의 당일 일정은 시작 시각으로 오름차순 정렬한다. 예시 수요일9:00메일확인→10:00제품미팅→15:30초안검토. 입력 예시 배열 자체는 의도적으로 뒤섞어 실제 정렬하는 코드를 검증했다.
- 시간이 없는 할 일은 시간 일정 아래 체크박스 항목으로 표시한다. 여러 날 일정과 단일 날짜 일정이 같은 항목처럼 반복되지 않게 제안했다.

### 기기별 시안
- Duo: 기존에 방향을 확인한 월~금5열 + 오른쪽 토/일 상하 배치, 별도의 카메라/내비게이션 예약 열 유지.
- 논 Duo: 카메라용 오른쪽 열이 없으므로 월~일7열을 나란히 배치하고, 표준 하단5탭 내비게이션과 상단 안전영역을 둔다. 토/일은 파랑/빨강으로 구분한다. 상태표시용 노치는 시안 장식이며 실제 하드웨어 geometry를 흉내내서 앱에 적용한 것이 아니다.
- 좁은 화면에서 긴 제목이 줄바꿈되는 시각 한계는 시안에서 보이는 그대로다. 원본 제목/일정을 삭제하거나 데이터 길이를 제한한 구현은 없다.

### 파일과 재현
- design-previews/docen-one-week/multi-day.html: 앞 시안을 보존한 별도 후속 파일. `?mode=standard`로 논 Duo 레이아웃 전환, 기본은Duo. 실제API/계정/앱페이지와 연결하지 않는다.
- design-previews/docen-one-week/capture-multi-day.mjs: `node design-previews/docen-one-week/capture-multi-day.mjs` 실행. 로컬 Chromium으로 합성 시안을 캡처한다.

## 후속 수정 — 시간표형 1주, 두 기기 모두 토/일 상하
사용자는 논 Duo의 월~일7열 제안을 정정했다. Duo·논 Duo 모두 토요일과 일요일을 같은 열의 위아래에 둬야 한다. 논 Duo 내비게이션의 docen.ai 글자는 제거하고 그림 아이콘만 남긴다. 평일은1시간 단위 가로선이 있는 세로 스크롤 시간표, 겹친 시간 일정은 좌우 나란히, 여러 날 일정은 위에 쌓이며 시간표를 밀어내고, 주말은 시간 간격에 비례하지 않는 시간순 목록을 요구했다. **이 요구의 산출물은 시안이며 앱 구현은 요청하지 않았다.**

### 주말 좌우 위치의 확인 상태
이전에는 오른쪽 토/일 배치였지만 마지막 문장에 ‘왼쪽’이라고 적혔다. 좌/우 확인 질문을 보냈으며 작성 시점에는 답변이 없다. 시안은 최신 문장의 왼쪽을 임시 기준으로 제작했다. 위치가 확정됐다고 기록하지 않는다. 사용자의 후속 답변이 우선한다. `?side=right` 또는 `WEEKEND_SIDE=right`로 다른 쪽 배치도 확인할 수 있다.

### 디자인·코드 구조
- design-previews/docen-one-week/timeline.html: 이전 index/multi-day 시안은 그대로 보존한 독립 합성 시안.
- `.week-layout`은 평일 영역과 주말 목록 영역으로 구성한다. `.left`일 때 주말 목록을 왼쪽, 평일을 오른쪽에 둔다. Duo의 물리 카메라/세로 내비게이션은 화면 가장 오른쪽의 별도 예약 열을 유지한다.
- 평일 제목 다음 `.spans`는 CSS grid의 실제 flow 영역이다. 여러 날 일정은 겹치는 날짜가 없는 행에 배정하며 화~수 등 동일 날짜를 사용하는 일정은 다음 행으로 쌓는다. 높이 증가가 flex의 실제 시간표 viewport를 줄이고 시작 y를 아래로 옮긴다. 기존 시간표 위에 겹쳐 그리는 방식이 아니다.
- 합성 예시: 월~화 제안 준비, 화~수 팀 워크숍, 화~목 문서 검토의3행. 추가 화~수 일정은4행이 된다. 막대는 날짜 열과 맞추며 접근성 라벨에 시작/끝 날짜를 포함한다.
- `.hour-scroll`만 세로 스크롤된다. 위의 제목·기간·요일·여러 날 영역은 고정된다. 전체24시간,1시간72px,가로선24개,초기08:00 근처. 세로 스크롤로 오전/오후 다른 시간대를 볼 수 있다.
- 시간 일정의 top/height는 시작/종료 시간 비례. layoutEvents는 시작 순으로 정렬해 서로 시간 범위가 연결된 그룹을 만들고 재사용 가능한 lane을 배정한다. 겹친 그룹만 최대 lane 수로 폭을 나눠 나란히 표시한다. 예시 수요일10:00~11:30제품회의와10:15~11:00디자인검토는2lane,9:00메일확인은전체폭.
- 주말은 같은 열 위 토/아래 일의 별도 목록. 토09:00→13:00→18:00,일10:00→15:00. 시간 차이가 큰 만큼 빈 공간을 만들지 않는다.
- 논 Duo도 같은 주말 상하 구조를 쓰며 카메라 예약 열을 제거하고 표준 하단탭을 둔다. AI탭의 img는 유지하고 표시 글자는 추가하지 않는다. 다른 탭 라벨은 그대로다.
- 화면이 좁으면 겹친 카드의 제목이 짧게/여러줄 표시된다. 실제 앱 제목을 자르거나 저장 데이터를 제한한 것이 아니다. 시안은 합성 자료이고 서버/API는 연결하지 않았다.

## 주말 위치 최종 정정 — 오른쪽 확정
사용자가 ‘갑자기 주말이 왜 왼쪽으로? 오른쪽으로 옮겨’라고 명시했다. 이전 왼쪽 임시 해석은 폐기하고 Duo·논 Duo 모두 오른쪽 토요일 위/일요일 아래로 확정한다. 위의 좌/우 미응답 기록은 과거 상태이며 더 이상 유효하지 않다.
- timeline.html 기본 side와 capture-timeline.mjs 기본 WEEKEND_SIDE를 right로 수정.
- 시간표 스크롤/1시간 가로선/같은 시간 좌우 lane/여러 날 스택에 따른 아래 밀림/논Duo AI탭 그림만 표시를 유지한다.
- 기존 왼쪽 캡처는 과거 증거로 보존하고, 수정 캡처는 artifacts/week-timeline-right-preview/에 별도 생성한다. 재현: node design-previews/docen-one-week/capture-timeline.mjs.
- 앱 소스·데이터·빌드·배포는 변경하지 않는다. 시안의 주말 위치만 수정했다.


## 현재 시각 가로선 — 오른쪽 주말 정정과 함께 추가
사용자는 시간이 지남에 따라 현재 시간대를 알려주는 가로선을 추가로 요청했다. timeline.html 시안의 시간표에 빨간 가로선·시작점·왼쪽HH:mm 시각표시를 추가했다. 시간과 높이를 비례시켜 현재시각(시+분/60+초/3600)×72px에 위치한다. 30초마다 갱신하며 화면 복귀 시 즉시 재계산한다. 초기 숨김/제거가 아니라 실제 Date를 읽는 시안 코드다. 사용자가 시간표를 보고 있을 때 자동으로 스크롤 위치를 옮기지는 않는다. 주말은 시간 간격에 비례하지 않는 목록이므로 빨간 선을 그 위까지 연장하지 않는다.
캡처 테스트에서만 Asia/Seoul,2026-11-25 10:30으로 브라우저 시계를 고정했다. 현재시각표시10:30/높이756px를 확인하고,30분을 진행시켜11:00/36px 아래로 이동하는 것을 검사했다. 실제 시안은 고정값이 아니라 브라우저 현지 시각을 사용한다. 카메라 열의 합성 시계도 같은 값으로 표시한다.
재현 명령 `node design-previews/docen-one-week/capture-timeline.mjs`의 기본값은right,결과 artifacts/week-timeline-right-preview/. 기존 레이아웃/스크롤/lane/스택 검사를 함께 통과했으며 세 화면을 열어 확인했다. 앱에는 아직 반영하지 않았다.


## 최신 시안 계약 — Duo·논 Duo·웹 3종 기본, 월 선택 오른쪽
사용자가 모바일/PC의 월 변경을 오른쪽으로 옮기고 모바일의 뷰 변경은 삭제, 웹은 월 옆에 뷰 변경을 두며 Duo·논 Duo·웹 시안을 다시 만들라고 지시했다. 추가로 앞으로 별도 지시 없이 시안을 요청하면 이 세 가지를 기본으로 만들어야 한다고 확정했다. Duo의 가로 화면을 웹(PC) 대신 제공하지 않는다.

### 고정과 스크롤의 구분
추가 메시지에서 ‘밑에가 길어져서 스와이프하면 여러 날은 고정이고 그 아래만 움직이는 것’이라고 명시했다. 제목/기간/요일/여러 날 일정의 상단 영역은 고정하고 시간표의 hour-scroll만 움직인다. 여러 날 일정이 늘면 고정 영역 자체가 커지고 시간표 시작점이 아래로 이동한다. 이는 스크롤할 때 여러 날 영역이 따라 움직인다는 뜻이 아니다. 새 시안에서 같은 구현을 유지하며 스크롤 전후 여러 날 막대의 실제 y좌표 동일을 검사했다.

### 세 화면 구성
- Duo 모바일: 오른쪽 월 선택, 뷰 변경 요소는 DOM에서 제거. 카메라 예약 열 및 세로 내비게이션 유지.
- 논 Duo 모바일: 오른쪽 월 선택, 뷰 변경 요소 제거. 하단 내비게이션, AI탭은 이미지뿐이며 글자 없음.
- 웹(PC): 실제 웹 레이아웃으로 별도 제작. 왼쪽 workspace 사이드바, 오른쪽 큰 캘린더 본문. 본문 헤더 오른쪽에 월 선택과 그 옆 뷰 변경을 배치. 모바일의 가상 카메라/노치/하단·세로 내비게이션은 웹에서 표시하지 않는다. ME 하위 메뉴/날씨 영역을 추가하지 않았다.
- 공통: 오른쪽 토/일 상하 목록,1시간 가로선,세로 시간표 스크롤,동시간lane,여러날스택,현재시각선30초갱신을 유지한다. 예시와 현재시각10:30은 캡처용 합성 자료다.
