# 간결한 채팅·Google 여러 계정·맞춤 브리핑 — 2026-11-14

> 후속 확정: 사용자가 2번을 선택하고 앱 전체 적용을 승인했다. 현재 구현/미검수 범위는 [완료 바 계약](keyboard-done-2026-11-14.md)이 우선한다. 아래 “시안만”은 선택 전 이력이다.

사용자 결정은 **키보드 내리기는 디자인 먼저, 나머지는 모두 구현**이다. 일반 iPhone 하단 탭과 Duo 카메라 열/가로 펼침의 왼쪽 고정 Calendar를 유지한다. 이번 구현은 60462e2의 native32 이후이며 새 앱 업데이트가 필요하다. 키보드 버튼/새 제스처는 선택 전까지 구현하지 않는다.

## 보내기와 대화 정리

- 정상적으로 전송을 시작하면 입력창을 즉시 비우고 보낸 말풍선과 실제 대기 상태를 보여준다. AI 응답을 받을 때까지 입력을 남겨두던 이전 동작을 폐기한다.
- 기다리는 동안 다음 글을 쓸 수 있다. 성공 응답이 다음 입력을 지우지 않는다. 실패 시 입력이 비어 있고 중간 편집도 없을 때만 원래 요청을 복구한다. 새 초안이 있으면 그대로 둔다.
- 오류의 ‘다시 보내기’는 실패한 원래 요청을 재시도한다. 새로 편집한 요청을 보내려면 입력창의 보내기를 누른다. 원래 요청 재시도가 별도 새 초안을 지우지 않으며, 자동 재전송하지 않는다. 같은 실패 말풍선은 재시도 때 대체한다.
- 대기 중 작업, 확인이 필요한 실행, 오류/결과 불확실은 유지한다. 오래된 실행 기록 목록·자료 개수/근거 footer·입력 앞＋는 본문에서 숨긴다. 방금 확인한 실행의 결과는 작은 행으로 확인할 수 있다. 기록/근거 데이터를 서버에서 삭제한 것이 아니다.
- 자료 선택·실행 기록은 **ME → 데이터·개인정보 → AI 자료·실행 관리**, 예약은 같은 페이지의 **브리핑·날씨 예약**에서 연다. ＋ 안의 단축 기능을 새 채팅 메뉴로 재설계하지 않는다. AI 없는 직접 입력/기존 단축 흐름은 유지한다.
- ME에서 자료를 바꾸고 돌아오면 유지 중인 채팅도 저장한 자료 선택/동의를 다시 읽는다. 범위 변경과 계정 전환 보호는 유지한다.
- 사용자/AI 턴은 생성 시각을 기록하고 서버에 저장된 브리핑 메시지와 시각순으로 합쳐 보여준다. 이미 도착한 브리핑이 새 질문 아래로 밀리는 별도 목록 배치를 폐기한다. 전체 대화의 앱 종료 후 복원은 이번 범위가 아니다.

핵심: `mobile/src/screens/AssistantChat.tsx`, `useAssistant.ts`, `screens/AssistantSheet.tsx`, `screens/ProfileScreen.tsx`, `screens/DuckScreen.tsx`, `mobile/App.tsx`.

## Google 계정 여러 개를 함께 연결

### 사용자 흐름

**ME → Google → Google 계정 추가 → 사용할 자료 선택 → Google 승인**. 계정은 최대10개다. 기존 계정을 바꾸지 않고 추가한다. 목록에서 계정을 선택한 뒤 그 계정의 자료/승인 기능/Tasks 완료 동기화/연결 점검을 관리한다. 권한 재승인은 선택한 계정으로 해야 하며 다른 Google 계정으로 승인하면 중단하고 ‘계정 추가’를 안내한다.

연결 해제는 선택한 한 계정의 확인을 거쳐 진행한다. 가져온 Todo는 보존한다. 다른 계정의 연결/대기 동기화는 지우지 않는다. 기본 계정을 해제하면 남은 계정을 구 앱의 기본 경로로 승격한다. 이미 선택한 추가 계정 캘린더의 복합 키도 계속 조회할 수 있다.

### 저장·원본 경계

`server/google-accounts.js`가 기존 `integrations(user_id,provider)` 암호화 행을 재사용한다. 원래 `google` 행은 구 앱의 기본 계정으로 유지한다. 추가 계정은 내부 `google:<connectionId>` 행에 같은 secretBox로 보관한다. 사용자/계정 식별자·기능·토큰 갱신 잠금을 분리한다. 로그인/서명/암호화 키를 초기화하거나 새로 만들지 않는다.

`connections(user,'google')`는 소유 계정들을, `connection(user,'google',connectionId)`는 해당 소유자의 특정 계정만 반환한다. 공개 상태의 `accounts`에는 선택 ID/이메일 이름/승인 기능만 담고 토큰을 담지 않는다. 토큰 갱신은 해당 connectionId에만 저장한다. 병렬 갱신, 재승인 도중의 오래된 응답, 다른 사용자 ID로의 접근을 검사한다.

새 OAuth 요청은 `mode:add` 또는 `mode:reauthorize`와 선택 connectionId를 보낸다. 구 클라이언트의 기본 경로는 유지한다. 추가 연결은 다른 계정의 가져오기 캐시를 지우지 않는다. 같은 외부 계정을 다시 승인하면 별도 중복 계정이 아니라 기존 연결 ID를 유지한다.

캘린더 목록은 읽기 권한이 있는 계정들을 합치고 이름에 계정을 구분한다. 추가 계정의 선택 키는 `@g/<connectionId>/<calendarId>`다. 서버는 키를 검증해 해당 사용자의 연결을 고른 뒤 Google 원본 ID만 고정 API에 사용한다. 동일한 event/list/task ID가 여러 계정에 있어도 섞지 않는다. 이미 보던 추가 계정이 기본으로 승격돼도 요청한 키와 목록 선택을 유지한다. 원본 페이지가 남은 계정은 계정/페이지를 묶은 cursor로 이어 읽는다. 일부 계정 조회 실패는 이전 목록과 함께 부분 실패로 표시한다.

일정 생성은 선택한 계정의 쓰기 가능한 캘린더에 한다. 수정/삭제는 event.connectionId와 캘린더 선택 키가 일치해야 한다. 원본 ETag/미리보기/한 번 실행/불확실한 결과의 자동 반복 금지를 유지한다. **기존 일정 이동은 같은 Google 계정 안의 캘린더 간만** 허용한다. 다른 계정으로 이동하는 선택은 막으며 복제/삭제로 몰래 대체하지 않는다. 메모/알림 보조 자료도 외부 계정 키별로 분리한다.

Google Tasks 완료 동기화는 계정마다 별도 opt-in이다. 가져온 Todo의 connectionId 접두어로 큐/원본을 찾고, 다른 계정을 끄거나 해제했다고 해당 큐를 지우지 않는다. Google Calendar·Gmail·Drive·Tasks 읽기와 명시 실행의 계정 라우팅도 분리한다. Apple/Outlook 계정 연결을 새로 구현한 것은 아니다.

## AI 동의와 예약의 계정 범위

Google 자료의 동의 지문은 연결된 모든 Google 계정 ID/외부 계정 ID/권한의 정렬된 목록을 포함한다. 토큰/만료시각 갱신은 지문을 바꾸지 않는다. 계정을 추가/해제하거나 권한을 바꾸면 이전 동의로 새 범위의 자료를 AI에 보내지 않는다. 자료 수집 전후 모두 확인한다. AI 출처 locator에는 필요한 계정 ID를 붙여 원본 제안의 계정을 고정한다. 자료는 기존처럼 최대85개/본문 예산 안에서 최근 일부만 읽고 한계를 알린다.

예약 저장 시 서버가 현재 범위를 기록한다. 연결 변경 후 이전 범위의 예약은 외부 자료를 AI에 보내지 않고 Todo 기반 안내와 재동의 안내로 대체한다. 범위가 없던 구 예약도 Google 계정이 여러 개면 자동 확대하지 않는다. 예약 화면에서 다시 동의하고 저장해야 한다. 사용자 대신 예약을 켜거나 AI 과금을 실행하지 않았다.

## ‘Dots’는 대화 맥락의 Pulse형 브리핑

사용자가 앞서 ‘ChatGPT처럼 먼저 보내달라’고 한 맥락으로, [ChatGPT Pulse 공식 소개](https://openai.com/index/introducing-chatgpt-pulse/)의 선제적 맞춤 브리핑을 뜻하는 것으로 이해했다. 현재의 [예약 작업 공식 안내](https://developers.openai.com/training/walkthroughs/scheduled-tasks)도 확인했다. 서비스 이름/현재 제공 여부를 추정해 덕에 ChatGPT 기능을 직접 연결했다고 말하지 않는다.

덕의 기존 매일 시간·시간대·도시·자료·반복 AI 동의·서버 메시지 보관/푸시 기반에 다음을 추가했다.

- **브리핑에 바라는 점**: 최대1,000자의 선호 요청을 예약에 저장한다. 예: 회의 준비와 오늘 마감 중심.
- 오늘 관련된 항목만 최대4~6개, 짧은 제목/나와 관련된 이유/다음 행동 순서로 요청한다. 자료가 적으면 억지로 개수를 채우지 않는다.
- 지난 브리핑 일부(최대1,800자)를 참고해 같은 내용을 길게 반복하지 않도록 요청한다. 이것은 모델에 주는 지시이며 반복이 항상 제거된다는 보장은 아니다.
- 받은 최신 브리핑을 현재 AI 대화의 제한된 문맥에 포함해 후속 질문을 이어갈 수 있다. 최근 대화 전체는 기존처럼 최대6턴/각2,000자다.
- 읽지 않은 뉴스/웹 정보를 만들지 않고, 실제 근거/조회 한계를 짧게 알린다. 외부 쓰기나 할 일 생성은 예약이 자동 실행하지 않는다.

**ChatGPT의 외부 대화/기억을 가져오는 기능, 야간 웹 심층 조사, 사용자의 반응을 영구 학습하는 추천 엔진은 구현하지 않았다.** 기존 무료 서버·예약 실행기의 지연 가능성과 실제 기기 알림 권한은 유지한다. 날씨는 AI 없이도 독립 예약할 수 있다.
