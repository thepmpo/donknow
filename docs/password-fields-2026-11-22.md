# 비밀번호 확인과 8자 생성 기준

## 적용

일반 회원가입·비밀번호 재설정에 비밀번호/확인란을 제공한다. 최소8자·최대128자·ASCII 숫자0~9·특수 구두점/기호를 각각 요구하며, 대소문자나 영문 의무를 추가하지 않는다. 공백을 특수문자로 세지 않고 비밀번호를 임의 trim하지 않는다. 첫 칸 아래 생성 기준을 항상 보인다. 입력/blur 뒤 기준 위반은 첫 칸·기준을 빨갛게 표시하고, 확인란 불일치는 빨간 테두리와 ‘비밀번호가 일치하지 않습니다.’를 바로 아래에 보인다. 웹의 검은 기본 포커스 outline이 오류 테두리를 덮지 않게 같이 조정했다. 접근성 invalid/설명/alert도 제공한다.

조건이 충족되고 확인란이 일치해야 버튼을 사용할 수 있다. 첫 비밀번호를 수정하면 확인란을 즉시 재검증한다. 첫 입력의 키보드 다음은 확인란으로 이동한다. 서버 /api/auth/register 및 /api/auth/password/confirm도 passwordConfirmation의 존재·일치를 검증한다. 로그인·계정 삭제는 기존 비밀번호를 검증하며 새 생성 조합 조건을 강제하지 않는다. 관리자 전용 암호 정책과 계정 분리는 변경하지 않는다.

## 인증 메일 답변

현재 회원가입 직후 자동 인증메일을 생성/발송하지 않는다. ME→내 계정→이메일 인증→인증번호 요청이 기존 흐름이다. 테스트는 가입 직후 mail_outbox가0건임을 확인했다. 실제 Resend 발신 도메인/수신 제한은 해결하지 않았다. 테스트 outbox 인증번호로 재설정 기능을 검증했으며 실제 수신 성공이라고 주장하지 않는다. 가입·재설정 자동 이메일 발송을 사용자 질문만으로 활성화하지 않았다.

## 호환성

일반 회원 API는8자 새 비밀번호의 가입·로그인·재설정을 지원한다. 기존10자 이상 비밀번호는 조합 조건을 다시 요구하지 않는다. 새 앱 소스는 동일하게8자 기준을 쓰고 삭제 화면도8자 계정을 차단하지 않는다. 이전 설치 앱에는10자 입력 제한이 남아 있어8~9자 비밀번호를 사용하려면 새 앱 빌드가 필요하다. 확인 필드가 없는 이전 클라이언트는 최신 앱 또는 웹 이용 안내를 받는다. 이번에는 웹 번들을 배포하며 native IPA/TestFlight를 실행하지 않는다.
