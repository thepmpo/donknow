# 미리알림 전체 가져오기·원본 완료 반영·연결 안정성 — 2026-11-16

## 사용자 확정

모든 목록에서 미완료만 가져온다. 덕에서 완료·되돌리기·내용·날짜·시간을 바꾸면 지원되는 연결 원본에도 같은 변경을 저장한다. 덕에서 직접 만든 항목은 덕에만 저장한다. 원본에 해당 기능이 없거나 권한/통신이 실패하면 실패 상태와 AI 채팅의 대안을 제공한다. 이 확정은 이전 foreground 완료 동기화 opt-in 제한보다 우선한다. 기존 예약/백그라운드 작업의 별도 동의·원본 권한·이메일 인증·ETag 보호를 대신 켜거나 우회하지 않는다.

## 전체 가져오기

기존 화면과 API는 각각20개 선택/전송만 허용했다. 이제 ‘전체 미완료 가져오기’로 접근 가능한 모든 목록을 읽고 전체를 선택한다. 확인 후 ‘선택한 N개 가져오기’를 누르면 끝까지 나눠 저장한다. 개별 목록/항목 선택도 유지한다. 전체 읽기는 EventKit의 incomplete 조건을 사용하고 날짜 범위를 걸지 않아 날짜 없는 항목과 지난 기한도 포함한다. 완료 이력은 가져오지 않는다.

전송 한 건의20개·256KB 서버 제한은 유지하고, 클라이언트가 UTF-8 크기를 고려해 여러 요청으로 나눈다. 목록은50개씩 화면에 그리지만 전체 선택/가져오기는 아직 그리지 않은 항목도 포함한다. 진행 수·추가 수·기존 수를 보여준다. 결과를 받지 못한 요청을 자동 재실행하지 않고 남은 ID를 선택한 채로 둔다. 사용자가 이어 가져오면 서버가 이미 저장한 동일 원본 ID를 기존 Todo로 돌려줘 중복되지 않는다. 일부 목록을 못 읽으면 성공한 목록을 지우지 않고 실패 목록을 표시한다. 재확인/권한/AI 채팅 대안을 제공한다.

## 완료·수정의 원본 반영

완료 체크는 기존 내용 편집과 다른 경로여서 Apple 원본 저장을 건너뛰었다. 서버의 source edit에 done을 포함하고, 일반 Todo 체크·되돌리기·AI/브리핑의 연결 Todo 체크가 같은 경로를 사용한다. Apple은 원본 ID를 읽어 completed만 바꾸고 다시 읽어 확인한 뒤 현재 개정의 기기 결과를 서버에 기록한다. 기존 제목/알람/반복을 덮지 않는다. 원본 수정 시각은 문자열 표기 대신 실제 시각을 비교해 같은 시각의 Z/.000Z 표기 차이를 충돌로 오인하지 않는다. 응답 유실·계정 교체·이전 개정·검증 실패는 성공으로 가장하지 않는다.

Google Tasks는 명시적인 덕 편집/체크에서 원본에 title/notes/due/status를 반영하며 별도 백그라운드 완료 전송 ON에 의존하지 않는다. 같은 변경을 기존 대기 큐가 다시 쓰지 않도록 조정했다. 원본 쓰기 권한·사용자 소유권·ETag와 불확실 쓰기 보호는 유지한다.

| 자료 | 원본 저장 범위 | 제한/대안 |
|---|---|---|
| 아이폰 미리알림 | 제목·메모·예정일/시간·완료/되돌리기 | 가져온 기기의 실제 EventKit 접근 필요 |
| Google Tasks | 제목·메모·예정일·완료/되돌리기 | Tasks 수정 권한 필요. 예정 시간은 원본 미지원 |
| Google Calendar | 제목·메모·날짜/시간 | 수정 권한 필요. 일정 자체에는 Todo와 같은 완료 상태 없음 |
| Slack·Notion·메일 등 읽기 자료 | 덕의 작업 기록 및 기존 비서가 제공하는 확인된 쓰기 범위 | 아무 메시지/페이지를 덕의 제목·메모로 통째로 덮거나 임의 완료 상태를 만들지 않음. 미지원 변경은 AI 채팅에 원본 확인·대안 안내 |
| 덕 직접 작성 | 덕에만 저장 | 외부 원본 호출 없음 |

완료 기능이 없는 원본을 덕에서 완료해도 원본 일정/메시지를 삭제하거나 읽음으로 임의 변환하지 않는다. 지원되는 다른 필드의 저장은 계속 가능하고, 미지원 완료만 별도로 표시한다. 지원 필드의 저장이 확인되면 캘린더 표시 snapshot에도 즉시 반영한다. 원본 쓰기 실패에는 모델 없이 소유자의 AI 채팅에 이유·재시도·원본 앱 대안을 남긴다.

## 불안정해 보인 원인과 확인 범위

- 확인된 코드 문제: 가져오기/연결 승인/점검 POST가15초 제한이었고 기존 iOS의 서버 기동 대기는 AI/일정 쓰기에만 적용됐다. 이제 명시적인 연결·가져오기·Todo 원본 쓰기도 건강 상태 GET으로 먼저 준비하고 긴 요청 시간을 허용한다. 세션 토큰은 대기 전에 고정하고 POST/PATCH/OAuth/원본 쓰기를 자동 재전송하지 않는다.
- 실제 서비스 조회 실패 뒤 저장된 계정 정보만 새로 읽으면 정상처럼 표시되던 부분을 바꿨다. 실제 자료 조회/연결 점검 성공 전까지 최근 오류를 유지한다. 계정 전환과 늦은 응답 보호를 유지한다.
- Slack/Notion 가져온 ID에 연결 prefix가 붙는데 원본 링크 코드가 prefix 없는 형식만 인식하던 문제도 수정했다. 원본 계정 접근 검사는 유지한다.
- 운영 로그03:12:44 UTC에서 기존 AI의 읽기 전용 model 접근 확인이 HTTP403이었다. 이는 Google/Slack의 실제 인증 실패를 증명하지 않으며, 예전의 Responses429 credit_balance_exhausted와도 구분해야 한다. 이 수정은 비공개 본문/키를 남기지 않고 허용된 오류 code만 진단에 추가한다. 생성 API·프롬프트·유료 요청을 새로 실행하지 않는다.
- 서비스별 실패 진단은 provider·상태·분류·GET/POST만 남긴다. 토큰·계정명·자료명·URL/query·외부 오류 자유문은 기록하지 않는다. 개별 사용자의 Google/Slack 현재 토큰 유효성은 앱 계정의 실제 점검 없이 확정하지 않는다. 단순히 무료 서버만의 문제로 단정하지 않는다.

## 검증

실제 인증 API로125개를 여러 번 나눠 가져온 뒤 세 번째 응답 유실을 재현했다.40개 확인 후 남은85개를 재개해20개는 기존으로 확인하고65개를 새로 추가했다. 최종125개·중복0이며 원본 메모/출처를 유지했다. Expo 화면에서도 합성 EventKit3개 목록·125개·완료 제외·남은 항목/진행 표시·이어 가져오기를 직접 조작했다. 기기 권한은 한 흐름에서 한 번 확인한다.

네이티브 어댑터 단위 검사는 같은 ID의 완료/되돌리기와 readback, 권한 실패·계정 이탈·검증되지 않은 쓰기 unknown을 확인했다. Google 원본 ETag/완료 상태·대기 큐 중복 방지·덕 전용 항목·미지원 완료 이후 정상 내용 수정·개인정보 없는 진단을 검사했다. 기존 연결 오류/늦은 응답 회귀와 생산 web export·타입 검사를 통과했다. 로컬 전체 검사427통과/실패0/기존 조건부1제외와 후속 캐시3검사를 확인했고, 최신 전체 결과는 CI에서 최종 확인한다.

브라우저의 native 어댑터는 합성이다. 실제 EventKit/iCloud/계정 동기화·물리 iPhone/Duo·실계정 원본 쓰기·실제 AI 모델 성공을 검증한 것으로 보고하지 않는다. iPhone에는 새 빌드/설치가 필요하다. 이전 native workflow 조회 Forbidden이 해결됐다고 주장하거나 유료 빌드로 우회하지 않는다.
