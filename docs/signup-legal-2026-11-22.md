# 실제 회원가입과 약관·개인정보 동의

## 결과와 검증 범위

이메일/비밀번호 가입과 로그인은 실제 Node/SQLite 서버 및 현재 Expo 웹 번들로 검사했다. 약관 필수 체크는 기본 OFF이고, 누락·체크 해제·안내 로딩 실패 시 계정 만들기가 비활성화된다. 안내 재조회 시 체크를 모두 해제해 새 버전을 자동 동의하지 않는다. 문서를 별도 탭에서 열어도 이메일·비밀번호 입력을 유지한다. 만14세이상 확인은 자기 확인이며 공적 나이 검증이라고 주장하지 않는다. 이름·생년월일·전화번호를 추가 수집하지 않는다.

브라우저 검사: 안내503→가입차단→다시확인, 개별 필수 체크, 문서 고정 버전 열람, 390px 화면, 실제 가입, 동의 버전/시각 저장, HttpOnly 쿠키, 새로고침 후 로그인 복원, ME 동의 조회, 로그아웃, 오입력 비밀번호 거부, 정상 비밀번호 로그인. 합성 계정만 사용했고 실메일·외부 서비스·모델 호출은 하지 않았다. 기존 전체 웹 CRUD/설정/자료 내보내기/계정 분리와 초기 HTML 웹 가입도 재검사했다.

전체 457개 중456개 통과·기존1개 제외·실패0. 문법121개, 모바일 TypeScript, Expo 웹 내보내기, 소개 사이트 빌드와 Sites 패키징 테스트 통과. 동의 기록의 libSQL HTTP 원격 DB 재시작 지속·계정 삭제 cascade도 검증했다. 마지막 문구 조정 후 정책/가입 대상6개 재검사 통과.

## 실제 동의 저장

/api/legal은 현재 문서 버전과 링크를 공개한다. /api/auth/register는 agreements.termsVersion·privacyVersion이 현재 버전이고 age14가 true인 경우에만 신규 HTTP 가입을 받는다. 사용자·동의·세션을 하나의 트랜잭션으로 저장하고 이메일 중복/동시 요청은 중복 계정이나 고아 동의를 만들지 않는다. 비밀번호는 scrypt 해시로 저장한다. signup_agreements에는 user ID·문서 버전·시각·14세 확인·web/native만 보관한다. 동의 증명을 이유로 IP·생년월일 등을 추가 수집하지 않는다.

기존 내부 이관/가입 계정의 동의 기록은 null로 유지한다. 로그인 시 이를 임의로 만들거나 시간을 덮어쓰지 않는다. 본인은 ME→내 계정→약관과 가입 동의 및 /api/account/agreements·개인 내보내기로 확인하고, 관리자는 기존 권한 안에서 동의 메타정보를 조회한다. 계정 삭제 시 함께 삭제한다. 앱의 User 타입·이용권 표시도 실제 Free/Lite/Pro 및 수동 발급에 맞췄다.

이미 설치된 이전 iPhone 앱에는 이번 필수 동의 UI가 없다. 기존 로그인은 유지하며, 이전 버전에서 신규 가입을 요청하면 최신 앱 또는 덕 웹에서 동의 후 가입하고 앱에 로그인하라는 메시지를 받는다. 네이티브 소스는 변경했으나 이번 작업에서 새 IPA/TestFlight 빌드를 실행했다고 주장하지 않는다.

## 문서와 비교 기준

- /terms: 가입 자격·계정, 기능 한계·장애, AI·문서, 외부 권한·원본 변경, 자료 권리, 무료 베타/이용권/유료 전환, 금지행위·비례적 제한/소명, 탈퇴·분쟁. PG 미연결과 향후 결제 전 별도 고지를 명시한다. 무조건 면책·해외 중재·일방 법원 강제를 복제하지 않는다.
- /privacy: 운영자/권리 문의, 필수 수집 항목·목적·보유/거부 효과, 선택 기능, 수탁사·국외 처리, 보관/파기, 권리/침해 구제, 안전조치·자동화 설명.
- /ai-policy: 선택 자료 전송·반복/기억 별도 동의, 결과 검토, 권리·모델 한계, 승인 실행·실패·기기 제한, 비용 한도.
- /cookies: 필수 로그인 쿠키·기기 캐시·제어 방법. 광고·행동 추적 동의를 가입에 끼워 넣지 않는다.

구조 비교: [Todoist 이용약관](https://www.todoist.com/terms-of-service)은 계정·AI 결과·외부 서비스·베타/결제 항목을 분리한다. 덕에는 실제 기능과 PG 미연결 상태를 적용했다. [Todoist 개인정보](https://www.todoist.com/privacy)와 [Any.do 개인정보](https://www.any.do/legal/privacy-policy/)의 항목/목적·공급자·보관·권리·쿠키 구조를 참고했다. 그 서비스의 마케팅/분석·위치·외국 아동 기준·사업자 주소를 덕의 사실로 복사하지 않았다. Any.do 약관 URL은 도구로 본문 조회가 되지 않아 읽었다고 주장하지 않는다.

대한민국 기준은 [현재 시행 개인정보 보호법 제28조의8](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029334869)에서 국외 처리의 근거와 고지 항목을 확인했다. 단순 체크박스가 확인되지 않은 국가·법인·보관 조건을 대신하지 않는다. [2026 개인정보 처리방침 작성지침 안내](https://www.privacy.go.kr/front/bbs/bbsView.do?bbsNo=BBSMSTR_000000000049&bbscttNo=20885)는 검색으로 확인했으나 전체 본문 도구 조회가 실패해 검토 완료로 표기하지 않는다.

## 남은 사실 확인과 공개 범위

Render 서비스 메타데이터의 싱가포르 리전은 확인했다. Turso DB/복제본의 실제 국가·Resend·GitHub 백업·OpenAI/푸시의 실제 계약 당사자/연락처·지역·보관 조건은 확보하지 못했다. 공개 개인정보 문서에 확인 필요 항목을 구분하고 사용자에게 DB 리전을 질의했다. 포괄 가입 동의로 이를 해결했다고 표시하지 않으며, 별도 국외 이전 동의가 필요하면 정확한 고지 후 동의를 받아야 한다. 이 항목이 남아 있어 스토어 제출용 최종 개인정보 정책 검토 완료 플래그는 false로 유지한다. 새 안내 버전 게시를 법적 검토·모든 운영 계약 확인 완료로 표현하지 않는다.

실제 이메일 발신 도메인 제한은 이번 구현으로 해결되지 않았다. 인증·비밀번호 재설정 코드는 테스트 메일함으로 검증했다. 실제 발송 성공이나 수신을 대신 검증했다고 주장하지 않는다.

## 이름 변경

새 서비스명을 사용자가 알려주면 먼저 변경 사실·적용일을 안내한다. legalIdentity를 수정하고 새 legalVersion으로 문서를 생성해 가입 링크·사이트·ME 안내를 함께 반영한다. 기존 /legal/{version} 본문과 동의 기록은 그대로 둔다. 운영 주체/자료 목적/제3자 제공까지 바뀌는 경우 단순 이름 바꾸기로 처리하지 않고 필요한 별도 고지·동의 절차를 검토한다. 현재 운영자/문의는 이전 사용자 확정값을 유지한다.
